# CLAUDE.md — правила для виконавця

Повний процес — `docs/process.md`. Що будуємо — `docs/concept.md`. Правила полів картки — `docs/rules.md`.
Тут коротко те, що виконавець тримає в голові завжди.

## Ролі й петля

- **Власник** (Влад) вирішує, мержить PR, переносить короткі фрази між чатами. Код не пише.
- **Архітектор** (Claude у Cowork) пише тікети в `.claude/tickets/`, читає дифф і звіти, ухвалює технічні рішення.
- **Виконавець** (ти, Claude Code у VS Code) пише код і тести, комітить у гілку тікета, пушить гілку, відкриває PR, лагодить свої червоні, пише звіт.
  Не мержить, не пушить у `main`, не ходить на сервер, не чіпає `.github/` без дозволу, не вирішує питань продукту чи безпеки сам.
- Кожна твоя зупинка (Фаза 0 готова, потрібне рішення, PR готовий) закінчується блоком:
  **«Для Власника: <що зроблено, простою мовою> · Скажи Архітектору: <фраза>»**.
- Великі тексти — у репозиторії (звіт у `.claude/handoff/<ID>.md`), через Власника йдуть лише короткі фрази.
- Новий тікет = нова сесія (`/clear`). Ітерації одного тікета — у тій самій сесії.

## Жорсткі правила проєкту

1. **Нічого не публікувати й не відправляти** на живу Шафу чи в живий Telegram-канал без окремого тікета й дозволу Власника.
2. **Секрети** (API-ключі, токени бота, сесії, cookies) — лише в `.env` поза git. Ні в код, ні в тести, ні в коміти, ні у звіт, ні в чат. `.env.example` містить лише назви.
3. **Реальні дані Продавчині** (Експорт, фото, її оголошення) — не в репозиторій. Тести — лише на фікстурах у `tests/fixtures/`, без мережі й справжніх ключів.
4. **Кросплатформність:** розробка на Mac, продакшн на Windows. `pathlib` замість рядків-шляхів, явне `encoding="utf-8"` при читанні й записі, кирилиця в назвах файлів і папок має працювати.
5. **Python 3.12** у продакшні: не використовувати можливостей новіших версій (ruff `target-version = "py312"`).
6. Залежності — лише закріплені версії (`==`).
7. Факти про код, API, бібліотеки й ліміти — з читання чи досліду, не з пам'яті.

## Ваги задач (називає Архітектор)

| Вага | Що це | Фаза 0 |
|---|---|---|
| **Дрібниця** | ≤ ~30 рядків без логіки, без файлу тікета | немає |
| **Звичайна** | усе між; бриф у `.claude/tickets/` | лише гіпотези (HYP) з брифу |
| **Критична** | безпека, секрети, доступи, дані користувачів, міграції, сервер, гроші, чужі API | повністю, **зупинка до коду** |

## Фаза 0 — звірка з реальністю (до коду)

1. Знайди всі файли, поля, бібліотеки, API, які називає тікет.
2. Кожну гіпотезу познач: **VERIFIED** · **DRIFT** (з `файл:рядок` або виводом) · **UNKNOWN** (не перевірити без Власника).
3. Звіряй з кодом і документацією, не з пам'яті.
4. Звіт у `.claude/handoff/<ID>.md`, зупинка: «<ID> фаза 0 готова».

DRIFT зупиняє, якщо міняє те, що будуємо, або вимагає вибору, якого виконавець не має права робити.
Якщо реальність лише безпечніша чи повніша — запиши у звіт і працюй далі.
При зупинці **не правити тікет сам** і не адаптувати архітектуру на свій розсуд — чекати рішення.

## Git

- Лише гілки тікетів: `feature/<ID>-…`, `fix/<ID>-…`, `chore/<ID>-…`, `docs/<ID>-…`. Прямих комітів у `main` немає ніколи.
- Створення: `git fetch && git switch -c <гілка> --no-track origin/main`; перший пуш `git push -u origin <гілка>`.
- Коміти дрібні, Conventional Commits: `feat:`, `fix:`, `test:`, `chore:`, `docs:`, `refactor:`. Кожен пункт тікета — окремий коміт.
- Шлях у main: гілка → робота → журнал останнім комітом → пуш гілки (Власник підтверджує) → PR → дочекатися перевірок і полагодити свої червоні → Архітектор каже «мерж» → **Власник мержить**.
- **Заборонено без Власника:** `push --force`, `reset --hard`, `rebase`/`merge` у спільні гілки, видалення гілок і тегів, `git pull` у `main`, зміни `.github/`, міграції проти реальної бази.
- Розгортання не автоматизується з CI.

Старі пости: `.venv/bin/python -m shafa import-old --export <папка експорту з фото> --list <номери.txt> [--db …]` (база — програми). Межі «старих / нових на день» — `SHAFA_DAILY_OLD` (10) / `SHAFA_DAILY_NEW` (0), разом ≤ 30; робот бере спершу нові.
Поля одного поста: `.venv/bin/python -m shafa rules --export <result.json> --post <номер>`.
ШІ-бланк: `.venv/bin/python -m shafa fill --db <файл.sqlite> [--root …] [--post N] [--limit K] [--dry-run]` — не більше 10 Карток за запуск; `--dry-run` нічого не надсилає. Пакетом: `fill --db … --root … --batch [--limit K]` (−50%, кеш), `--estimate` (що піде і скільки — без запитів), `fill --db … --collect` (забрати результати). Інструкція для ШІ — `src/shafa/prompts/blank.md` (правиться без коду; зміна, після якої ШІ може відповісти інакше, — підняти `ai.PROMPT_VERSION`, дописати `ai.PROMPT_CHANGES` і підняти `rules.RULES_VERSION`; зміна лише коду — лише `RULES_VERSION`, програма перерахує бланки сама). CORE-007: код поверх ШІ — група розділу за словом і розміром (≤ 39 жіноче, ≥ 43 чоловіче, 40–42 ШІ, малюки ≤ 22), «сапожки» → Чоботи, сезон, «ідуть на», підкладка синонімами, до 2 кольорів, одне фото; сумнів ШІ там, де вирішив код, жовтим не робить.
Windows: збірка на Mac — `.venv/bin/python ops/build_windows.py lock | build` (вбудований Python 3.12.10, `ops/windows/requirements.txt` з контрольними сумами, програма — лише файли з git) → `dist/shafa-windows-<версія>.zip`; на ноутбуці «Встановити» → `%LOCALAPPDATA%\shafa\app\`, ярлик на `pythonw.exe -m shafa app`; інструкція — `docs/install-windows.md`. Команди: `app [--no-browser]`, `quit`, `setup`.
Екран перевірки: `.venv/bin/python -m shafa ui --db <файл.sqlite> [--root …] [--port 8765] [--no-browser]` — відкриває браузер; Ctrl+C зупиняє.
Робот (живий сайт — лише з дозволу Власника): `.venv/bin/python -m shafa robot --login` (Власник входить руками) · `--sync-catalog` (знімок довідників, ~2 год, лише читання) · `--dry-fill --db <файл.sqlite> --post N [--post M …]` (до 3 Карток, форма заповнюється, **не публікується**, скріншоти в теці даних) · `--publish --db <файл.sqlite> [--limit N]` (**публікує** схвалені; лише з дозволу Власника) · `--rehearse --db … [--sections | --post N …] [--count N]` (QA-003: пробний прогін, типово 5 завтрашніх Карток, до 30; нічого не публікує; Схвалені з помилкою — в «Проблеми» з «Пробний прогін: …») · `--pause` / `--resume` / `--stop --db …` (керування запущеною публікацією). Другий запуск при живому роботі — «Робот уже працює» (код 2), нічого не чіпає. З екрана — кнопки панелі (той самий процес `robot --publish`, журнал — `robot-run.log` у теці даних).
Бот: `.venv/bin/python -m shafa bot --db <файл.sqlite> [--root …] [--check]` (`--check` — лише токен і права в каналі; другий запуск — «Бот уже працює», код 2). Публікує лише в `TELEGRAM_BOT_CHANNEL_ID` (окремо від `TELEGRAM_CHANNEL_ID` для назв папок): спершу тестовий канал, її — лише з дозволу Власника.
Налаштування (`SHAFA_ROOT_DIR`, `TELEGRAM_CHANNEL_ID`, `TELEGRAM_BOT_TOKEN` (секрет), `TELEGRAM_BOT_CHANNEL_ID`, `TELEGRAM_SELLER_CHAT_ID`, `TELEGRAM_OWNER_CHAT_ID`, `ANTHROPIC_API_KEY`, `SHAFA_DATA_DIR`, `SHAFA_DAILY_LIMIT`, `SHAFA_DELETE_PUBLISHED` — видаляти папки з «Опубліковано» і фото старих постів (`<дані>/borh/`) через 3 дні, типово вимкнено; `SHAFA_AI_WAIT_DAYS` — 7, `SHAFA_AI_BATCH_LIMIT` — 50, `SHAFA_AI_DAILY_USD` — 3, `SHAFA_LISTINGS_DAYS` — 7, `SITE_INTEGRATION_KEY` (секрет, необов'язковий), `SHAFA_SITE_SEND` — відправляти на сайт, типово ні; `SHAFA_ASK_BUTTON` — «Пишіть сюди» в постах бота є посиланням «Запитати», типово так, «ні» — простий текст; `SHAFA_SITE_BUTTON` — рядок-посилання «Більше взуття на сайті», так само; `SHAFA_SITE_WAIT_DAYS` — 7, `SHAFA_SOLD_CHECK` — так; `SHAFA_REHEARSE_AT` — «ГГ:ХХ» нічного пробного прогону, порожнє — вимкнено, типово вимкнено; `SHAFA_REHEARSE_COUNT` — 5; `SHAFA_REPORT_AT` — година щоденного звіту Власнику, типово 21:00, порожнє/`off` — вимкнено; `SHAFA_ALERTS` — тривоги Власнику одразу, типово так, `off` — вимкнено) — зі змінних середовища або з `.env`.
Справжні дані й базу — лише поза репозиторієм.

## Перевірки

- `make setup` — `.venv` і dev-залежності; `make ci` = `make lint` + `make test`. Те саме, що в CI. Ганяти перед пушем.
- На PR — `quality` (Ubuntu, Python 3.12) і `windows-tests` (Windows; стартує лише після зеленого `quality`). `windows-package` (збірка пакета й димова перевірка на чистому Windows) біжить на PR лише коли змінено пакування/встановлення (`ops/`, `install.py`, `wizard.py`, `app.py`, `config.py`, `places.py`, `pyproject.toml`), і вручну: Actions → windows-package → Run workflow — перед випуском для Вікторії. На `push: main` перевірок немає. Захисту `main` на GitHub немає (TD-002): мерж лише коли зелені `quality` і `windows-tests` (і `windows-package`, якщо він біг або це випуск). Пуш гілки — один раз у кінці, не після кожного коміту.
- Тест доводить головне: **якщо прибрати фікс, тест червоніє.** Перевір це і напиши у звіті.
- Інтеграції (Telegram, Шафа, Claude API) — тести на моках і фікстурах.

## Звіт (handoff)

Файл `.claude/handoff/<ID>.md`, 10–15 рядків, максимум 40, оновлюється поверх. Шаблон — `.claude/templates/handoff.md`.
Довгі виводи й таблиці — в опис PR, не у звіт. Після мержу звіт переноситься в `.claude/archive/handoff/` першим комітом наступної гілки.

| `LEARNED_CONVENTIONS.md` | уроки `LC-NNN`, лише з другого повтору | виконавець |

## Ритуал сесії

**Старт** («продовжуємо», «поїхали» або назва тікета). Прочитай: `CLAUDE.md` → `.claude/state/STATUS.md` →
три останні записи `.claude/state/log/` → `docs/TECH_DEBT.md` → `OPEN_QUESTIONS.md` → заголовки `LEARNED_CONVENTIONS.md`.
Перевір гілку, чистоту дерева і хуки: `git config core.hooksPath` має бути `.githooks`, інакше `sh ops/install-hooks.sh`.
Перша відповідь починається рядком:

`[Pre-flight: CLAUDE ✓ | LEARNED ✓ | SESSION_LOG ✓ | TECH_DEBT ✓ | OPEN_Q ✓] гілка: <…>, тікет: <…>`

**Кінець** («на сьогодні все»): запис у журнал новим файлом, останнім комітом гілки. Дату брати командою `date`.
