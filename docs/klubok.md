# Клубок — проєкт змін (Архітектор · 10.11.2026)

Мета: пари Вікторії, схвалені в програмі, автоматично йдуть ще й на Клубок (klubok.com).
Одна перевірка Картки — для обох сайтів. Темп 10 → 20 → 30 пар/день, спершу зимове.
Дослідження: проєкт Shafa `claude/klubok-analiz-10-11.md`, `claude/klubok-doslid-10-11.md`; сторінки редагування — `~/klubok-4` (не в репо).
Цей файл — `docs/klubok.md` (перенесено в KLB-001; далі його ведуть тікети KLB-002…005).

## Рішення Власника (10.11)
1. Піврозмір → **обидва** цілі (38,5 → 38 і 39).
2. Пост зник з каналу → оголошення в список **«Схоже, продано»**; лише після «Так, продано» Вікторії програма знімає його з Клубку і більше не оновлює. Без підтвердження — нічого.
3. Зміна ціни/тексту в каналі після публікації на Клубку — **не чіпаємо**.
4. З дня запуску Вікторія сама на Клубок не виставляє (дату — при запуску).

## Принципи
- **Шафа не змінюється.** `items.status` — лише Шафа. Клубок має **свою таблицю** зі своїм станом і id.
- **Без ШІ.** Поля Клубку рахує код з Картки (вона вже перевірена) і тексту поста.
- **Захист як у Шафи:** свій `guard` (клік, мережа), квиток на одну публікацію, підставний Клубок для тренувань. **На Клубку небезпечні дії — GET-посилання** (`/renew/all`, `?pg=renew-used`, `?pg=marksold`): guard блокує їх і для GET; навігація — лише за списком адрес.
- **Робот Клубку — окремий профіль Chrome** (`<дані>/klubok-profile/`), але **той самий замок** `robot.lock`: ніколи два Chrome одночасно (слабкий ноутбук).

## Що в Картці → що на Клубку (код, `src/shafa/klubok/fields.py`)
| Клубок | Звідки |
|---|---|
| Название (`item_name`, ≤ 100) | `title` Картки (формат той самий: «… N розміру в … стані») |
| Описание (`text`) | перше речення поста (без ціни) + порожній рядок + `description` Картки (її правки діють) |
| Стоимость | ціна **з поста** (`rules.price_from_text`), не ціна Шафи |
| Категорія (3–4 рівні) | таблиця «група + тип Шафи + сезон → шлях Клубку» (`klubok/category.py`), id — зі знімка |
| Пол (`sex`) | лише дитячі категорії (у дорослих поля немає): `rules.said_gender` — дівчинка 0, хлопчик 1, інакше 2 «Любой пол» |
| Состояние | «Новий» → 1 «Новое», інакше 0 «Б/у». «Сток» — ніколи |
| Размер (`size[]`) | цілі; піврозмір → обидва; значення мають бути в списку розмірів категорії |
| Цвет | перший колір Картки за таблицею UA → ключ Клубку; «Різнокольоровий» або ≥ 3 → 99; немає відповідника → не ставимо |
| Бренд | `brand` Картки; з підказки Клубку — пункт «Бренд (Кирилиця)», чий початок = бренд; немає — вільний текст (живу поведінку перевіряє KLB-003) |
| Фото | порядок Картки, ≤ 15, **по одному**, кожне після завершення попереднього; звірка порядку з `formData.images` |
| Характеристики, доставка, служби | не чіпаємо (за замовчуванням, як у неї) |

Чого не вистачає → Картка на Клубок не йде, причина-код (`klubok_no_category`, `klubok_size`, `klubok_no_price`, `klubok_title_long`). Шафи це не зачіпає.

## Черга й ліміт (KLB-002, зроблено — `src/shafa/klubok/queue.py`)
- **Кандидат:** `items.status` `approved`/`published`, не очищений архів, пост > `SHAFA_KLUBOK_FROM_POST` (типово 7200), рядка `klubok_ads` немає або він `queued`/`skipped` (крім її «Так, дубль»). `publishing`/`problem` Шафи — ні.
- **Вердикт** (`plan` — нічого не пише; `sync` — пише, чіпає лише `queued`/`skipped`, рядки Карток, що вже не кандидати, видаляє; «Скасувати схвалення» прибирає `queued` одразу): `skipped` з кодом `fields.ad` (`klubok_no_category`, `klubok_size`, `klubok_no_price`, `klubok_title_long`, `klubok_no_title`, `klubok_no_photos`), `klubok_post_gone` (нічна перевірка: пост зник, `publish.known_gone`), `klubok_post_done` (інша Картка поста, не сестра-розмір, уже `publishing`/`published`/`sold_asked`/`sold`/`removed` чи `problem klubok_uncertain`); `problem klubok_duplicate` (нижче); інакше `queued`.
- **Порядок:** зимове (сезон містить «Зима»; порожній — з тексту) → інше → лише «Літо»; усередині — старіші пости (`posts.date`, далі `items.id`).
- **Ліміт доби** `SHAFA_KLUBOK_DAILY_LIMIT` (типово 10, 1–30): спроби за місцеву добу за `klubok_ads.publish_started_at` — спільна `publish.started_on` (та сама, що й у Шафи). Ліміти незалежні. Спроба, що повернулась у чергу (`release`), лишається в ліміті; якщо ту саму Картку запустити знову того ж дня, `start` перезапише час — дві спроби однієї Картки за добу рахуються як одна (похибка ≤ 1 на добу, KLB-003 DRIFT-3).
- **`take(conn, root, today, post_id=None)`** → `Taken(cards, code)`: порожньо з причиною, коли Клубок вимкнено (`SHAFA_KLUBOK`, типово ні), знімка її оголошень немає чи він старший за 24 год (`klubok_snapshot_old`), ліміт вичерпано, у черзі нічого (`klubok_queue_empty`); інакше `sync` і по порядку до ліміту, кожна Картка ще раз перевіряється на дубль перед видачею. `post_id` — лише Картки цього поста (фільтр до обрізання за лімітом).
- **Стани:** `start` (`queued → publishing`, `publish_started_at`, `session_id`), `release` (`publishing → queued`: запит публікації точно не пішов; `publish_started_at` лишається), `published` (`klubok_id`, `url` — може бути NULL, його допише знімок), `problem`, `recover` (`publishing → problem klubok_uncertain` «Перевірте на Клубку, чи опубліковано», повтору немає) — кожен в одній транзакції з умовою на поточний стан.
- **Місце в черзі** (`place`, KLB-003 D7): лише рядки `queued`, порядок як у `plan`, без пошуку дублів, без `fields.ad` і без запису (на синтетиці 1787 оголошень × 48 у черзі — ≈ 7 мс замість ≈ 0,3 с). Картка без рядка — «у черзі» без номера.
- **Дублі** (`src/shafa/klubok/dup.py`): її активні (`klubok_listings`, `sold = 0`) і виставлені програмою (`klubok_ads` `publishing`/`published`). Правило — `listings.similar`/`sizes_close`/`prices_close`: розміри оголошення — з назви («38,5 розміру», «27-28 розміру», «40,5 размера»), бренд — `brand` рядка, а якщо NULL — бренд Картки (без уточнення в дужках, лише літери й цифри) **міститься в назві**; Картка без бренду — бренд не перешкода; категорія — лише коли `category_id` відомий (перший рівень Женское/Мужское/Детское); невідоме не перешкоджає (сумнів — Проблема). Сестри-розміри поста й оголошення Карток того самого поста — не дублі. Кириличних назв брендів у знімку Шафи немає. Рішення на Картці: «Інша пара — виставити» → `dup_ok_at`, `queued`, дублі більше не перевіряються; «Так, дубль — не виставляти» → `skipped klubok_dup_yes` (назавжди), її оголошенню без поста — `post_id` Картки.
- **Фото** (`folders.photo_folder`): `item_folder`, а для опублікованого на Шафі — `<Головна>/Опубліковано/<папка>`. `purge_published` і `borh.purge_photos` не стирають фото поста, поки `queue.needs_photos`: рядок `queued`/`publishing`/`problem` або кандидат без рядка — **незалежно від `SHAFA_KLUBOK`**. Уже стерті — `skipped klubok_no_photos` (TD-070: брати фото з оголошення на Шафі).
- **Стать дитячого:** розділ Картки («Для дівчаток» 0, «Для хлопчиків» 1), інакше слово в тексті, інакше 2.
- **Екран:** на Картці рядок «Клубок: у черзі · місце N / не піде: … / публікується / виставлено ДД.ММ.РРРР · Відкрити на Клубку / Проблема: …» (коли Клубок увімкнено або рядок уже є; GET нічого не пише), для дубля — назва й посилання схожого і дві кнопки; над Проблемами — «Клубок: треба рішення» (лічильник вкладки — лише Шафа). Налаштування — блок «Клубок».
- **Пробний прогін:** `python -m shafa klubok-queue --db <копія> --root <Головна> [--today РРРР-ММ-ДД]` — файл `mode=ro`, копія в пам'яті мігрує, файл не змінюється; ≤ 60 рядків.

Справжній запис — лише зі свіжим знімком (≤ 24 год). `--dry-run` — копія бази в пам'яті, файл і диск не змінюються; звіт ≤ 60 рядків.

## Публікація (KLB-003 — `robot/klubok_publish.py`, `klubok/snapshot.py`, `robot/klubok_form.py`, `robot/klubok_guard.py`)
Перші 1–3 — при Владі, після мержу; живого Клубку в тестах немає (лише підставний `klubok_fake`).
- **Вхід:** `python -m shafa robot --klubok-login` — видимий Chrome з профілем `<дані>/klubok-profile/`, сторінка `https://klubok.com/item/add` (без входу сайт веде на `/signup`); вводить людина, без guard, той самий замок робота. Пароля в програмі немає.
- **Перевірка входу** на початку сесії й перед кожною Карткою: форма `#addItemForm` і `#user_id` = 198135, інакше стоп `klubok_login` «Увійдіть у Клубок: python -m shafa robot --klubok-login».
- **Знімок** (`python -m shafa robot --klubok-snapshot --db …`, та сама функція на початку й наприкінці сесії): `fetch` усередині сторінки (cookies сесії, крізь guard) `GET /api/get-items?user_id=198135&type=0&sort=date&limit=3000&offset=0` — **один запит** на весь список (KLB-006). Відповідь: `{items, items_count, tabs_count, status}`; запис — `id`, `name`, `price`, `sold`, `moderated`, `renew_date`, `link` (`https://klubok.com/item-<назва латиницею>-<id>`), `img_link` (фото). Порядок `sort=date` — за `renew_date` зростанням: нове оголошення — у кінці списку. Повний — лише коли унікальних id = `items_count`. KLB-006: посторінково (`limit=60&offset=N`) список нестабільний — після «Обновить все» `renew_date` однакова до секунди в сотень оголошень (11.11: 29 значень на 1787), а сайт сортує без другого ключа, тож між запитами з різним `offset` частина id приходить двічі, частина — жодного разу (живий знімок 11.11 двічі: «1782 різних з 1787»). Один запит з `limit=3000` віддав усі 1787 з `items_count` 1787. Запасний шлях — сайт віддав менше за `items_count`: до 3 посторінкових проходів (пауза 1–2 с між сторінками, 60 с між проходами, разом ≤ 90 сторінок), записи об'єднуються за id (свіжіший перемагає), повний — коли об'єднаних id = `items_count`; не зійшлось — стоп `klubok_snapshot_failed`, нічого не пишемо. Запис в одній транзакції: upsert за `id` (`post_id`, `asked_at`, `brand`, `category_id`, `added_at` не чіпаються), `sizes` — з назви, `url` — лише `https://klubok.com/…`, `photo` — лише `https://img.klubok.com/…`; чого немає — `sold = 1`; `klubok_listings_read` (`read_at` UTC, `count` активних). Помилка / не JSON / HTTP ≠ 200 — нічого не пишемо, `klubok_snapshot_failed`; 429 — `klubok_429`; активних менше ніж 90 % від попереднього `count` — нічого не пишемо, `klubok_snapshot_drop` (рішення людини).
- **Сесія** `python -m shafa robot --klubok-publish --db … --root … --limit N [--post P] [--human-click]` (`--limit` обов'язковий, 1–30; `--post` — лише Картки поста): відкриті сесії Клубку після обриву → `crash` (сесій Шафи не чіпає), `queue.recover`, рядок `sessions` (`site = 'klubok'`), вхід, знімок, далі по одній: `take` (щоразу заново) → `start` → свіжа форма → заповнення й звірка (KLB-001) → квиток → клік `#btn-submit` (або людина, `--human-click`: «Перевірте форму й натисніть „Опубликовать“ унизу форми — чекаю 10 хв») → відповідь `add-edit-used` ≤ 60 с. Помилка форми до кліку — Проблема з кодом KLB-001, далі наступна. Між Картками пауза 60–180 с. Ctrl+C — поточна Картка доробляється (відповідь дочікується), потім стоп; Chrome від Ctrl+C не закривається. Кінець: `ended_at`, `stop_code`, `stop_reason`, `published`, `problems`; звіт у термінал ≤ 15 рядків; гучна подія `klubok.stop` для `klubok_captcha`, `klubok_uncertain`, `klubok_login`, `klubok_429`, `klubok_snapshot_*`, `klubok_forbidden`, `klubok_error`; тиха `klubok.end` інакше.
- **Відповідь** (тіло береться в обробнику маршруту — `route.fetch` → `route.fulfill`, — бо сторінка одразу йде на `/payment/…`, і в Chrome його вже не прочитати): `status == "success"` і `used_id > 0` → `published` з `klubok_id`, `url` NULL (на Картці «виставлено ДД.ММ.РРРР» без кнопки); `status == "Error"` → Проблема `klubok_captcha` «Клубок не прийняв: захист від роботів (оцінка …). Перевірте на Клубку, що оголошення немає.» і стоп; запит пішов, певної відповіді немає (тайм-аут, HTTP ≠ 200, не JSON, інший `status`) → Проблема `klubok_uncertain`, стоп, **повтору немає**; запит не пішов → `release`, стоп `klubok_not_sent`, список заблокованого — у файл `robot-screens/<час>-klubok-blocked.txt`; 429 від Клубку на будь-якому запиті → стоп `klubok_429` (до кліку — Картка назад у чергу).
- **Кінець сесії:** виставлено ≥ 1 — ще один повний знімок: дописує `klubok_ads.url` за `klubok_id` і звіряє — виставленого id немає в її списку → гучна подія `klubok.missing` «Оголошення {id} не видно в її списку на Клубку — перевірте» (стан не міняється). Знімок не вдався — лише рядок у лог.
- **Guard публікації** (лише в сесії публікації; dry-fill і знімок — як були): квиток на одну Картку видається після звірки й пропускає **один** POST рівно `https://klubok.com/api/add-edit-used`, другий — блок; клік «Опубликовать» — лише `#btn-submit` з живим квитком і не в `--human-click`; POST на чужий хост — лише `https://www.google.com/recaptcha/…` (reCAPTCHA v3). `/payment/{id}` і `/error429` заблоковані: після відповіді це очікувано (позначка в журналі заблокованого), на них нічого не відкривається й не тиснеться. Що саме кличе reCAPTCHA наживо — видно в списку заблокованого (HYP-3). Без прихованих хитрощів проти виявлення автоматизації: якщо reCAPTCHA не пускає й з `--human-click` — рішення Власника.

### Перша жива публікація 11.11 (KLB-007)

Сесія 62, `--human-click`, пост 7233: Клубок створив оголошення 37977926 — назва, розміри 37 і 38 (піврозмір → обидва), стан б/у, категорія «Женские зимние ботинки», ціна 1900 — усе правильно. Підтвердилось: reCAPTCHA v3 пропустила людський клік; бренд, якого немає в довіднику Клубку (Dachstein), іде вільним текстом. Знахідки: у відповіді `add-edit-used` `used_id` прийшов **рядком** — `_parse` приймає тепер число чи рядок лише з цифр (> 0; `bool` і решта — невпевнено, у журнал сесії йдуть тип і значення `used_id` та перші 300 символів відповіді); вікно Chrome з `viewport 1400×1000` було вищим за екран ноутбука — `LiveSession` відкривається з `no_viewport` (розмір вікна = вікно Chrome).

`python -m shafa robot --klubok-confirm --db … --post P --klubok-id N` — людина підтверджує, що невпевнена публікація відбулась (лише база, Клубок не чіпається; не під час живої сесії робота). Умови: одна Картка поста P у `problem` з кодом `klubok_uncertain`; оголошення N є в знімку (`sold = 0`), не прив'язане до іншої Картки; знімок не старший за добу (інакше «спершу `--klubok-snapshot`»). Результат: `published`, `klubok_id`, `url` зі знімка, `published_at` = зараз, `problem_*` порожні — одним UPDATE з умовою на стан; відмова — база не змінюється.

## Екран: вкладка «Клубок» (KLB-009 — `web.py`, `klubok/screen.py`, `robot/klubok_control.py`)
- **Перемикач угорі «Шафа | Клубок»** (`base.html`) на всіх сторінках. Шафа — як була (`/` → `/review`); Клубок — `/klubok/…`. Вкладки Клубку (лічильники, пошук як у Шафи — назва, бренд, номер, текст):
  - **«На перевірку»** (`/klubok/review`) — Картки «лише Клубок» (`only_klubok = 1`) у `review`;
  - **«У черзі»** (`/klubok/queue`) — рядки `queued` у порядку черги (`queue.order` — той самий, що й `place`: хвиля, зимове → інше → лише літнє, далі дата поста), номер і хвиля. Рядки пише `queue.sync`: на «Старт», «Схвалити для Клубку» (`sync_one`), рішеннях про дубль і кнопці **«Перерахувати чергу»** (`POST /klubok/sync`). Схвалене в Шафі після останнього перерахунку видно рядком «Ще N схвалених пар не перераховано» (`queue.unsynced`). GET нічого не пише;
  - **«Треба рішення»** — `problem` (дубль, «перевірте, чи опубліковано», помилки форми й захисту); **«Виставлено»** — `published` (дата, «Відкрити на Клубку» лише для `https://klubok.com/…`); **«Не піде»** — `skipped`, групи за причиною (`queue.REASONS`), найбільші першими.
- **Картка** `/klubok/item/N` (той самий `card.html`, `site = "klubok"`): блок **«Як буде на Клубку»** (`screen.ad_view` ← `fields.ad`, без пошуку дублів): назва, ціна з поста, шлях категорії, розміри, стан, стать (дитяче), колір (немає відповідника — жовтим), бренд, фото в порядку (запасне — позначено), хвиля, опис; не піде — жовтим причина. Рядок «Клубок: …» — як на Картці Шафи.
  - Картка «лише Клубок» у `review`: поля правляться як у Шафі (жовті, «Так, вірно», «Це жіночі/чоловічі»), кнопки **«Схвалити для Клубку»** (`review.approve_klubok` + `queue.sync_one` → одразу в «У черзі»; заборонено, якщо `fields.ad` каже «не піде» або розділ порожній / не з довідника / жовтий / немає розміру — колір і стать Клубку не обов'язкові), **«Не виставляти»** (`review.reject_klubok`: Архів, `problem_code = klubok_not_for`, через 7 днів очищується) і «Далі →» (та сама вкладка й пошук).
  - Картка Шафи — лише читання + «Відкрити в Шафі» (`/item/N`); кнопки Шафи тут не діють.
  - Дубль — «Інша пара — виставити» / «Так, дубль — не виставляти» (як KLB-002).
  - «Перевірте, чи опубліковано» (`klubok_uncertain`): поле «номер оголошення на Клубку» (цифри чи посилання `https://klubok.com/…-N`) → `queue.confirm` (KLB-007: свіжий знімок, оголошення в ньому, не прив'язане); **«Ні, не опубліковано — повернути в чергу»** → `queue.retry` (лише `problem klubok_uncertain` → `queued`, інакше відмова; подія `klubok.retry`). Обидві — не під час роботи робота (замок).
  - Блок «Клубок: треба рішення» над Проблемами Шафи веде на Картку Клубку.
- **Панель робота Клубку** (`klubok_panel.html`, опит `/klubok/panel` кожні 5 с; на Картці — міні): «Сьогодні на Клубку X з ліміту», «У черзі», дата й кількість знімка, підсумок останньої сесії простими словами (`klubok_control.LAST`, далі `klubok_publish.STOPS` / `queue.REASONS`). Під час сесії — «Виставлено X з N у цій сесії», «Зараз: пост P — заповнює форму / натискає «Опубликовать» / пауза — наступна за ~M хв», «Останній: …» (з `klubok-now.json`, `klubok_publish.write_now`).
  - **«Старт»** → `robot --klubok-publish --db … --root … --limit N` (N = ліміт доби − почато сьогодні), окремий процес (`control.spawn`), журнал `klubok-run.log`; з підставним режимом екрана — `--fake-klubok`. Недоступний (з причиною): Клубок вимкнено, налаштування з помилкою, ліміт вичерпано, у черзі нічого, працює будь-який робот (спільний замок; на панелі Шафи — «Зараз працює робот Клубку», `control` код `busy_klubok`). `--human-click` з екрана немає.
  - **«Пауза» / «Продовжити» / «Стоп»** — ті самі `sessions.command`, що й у Шафи (`publish.request(…, site="klubok")`; команда Шафи сесію Клубку не чіпає). Стоп = Ctrl+C (поточна пара доробляється, далі `stop`); Пауза — між парами: сесія чекає (`TICK` 2 с), доки не натиснуть «Продовжити» чи «Стоп». Наприкінці сесії `command` очищується.
  - **«Увійти в Клубок»** → `robot --klubok-login` (кнопка «Вхід виконано — закрити вікно» — той самий прапорець, що й у Шафи); **«Перечитати мої оголошення»** → `robot --klubok-snapshot --db …`.
- Налаштування — блок «Клубок» як був.
