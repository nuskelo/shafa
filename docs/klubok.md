# Клубок — проєкт змін (Архітектор · 10.11.2026)

Мета: пари Вікторії, схвалені в програмі, автоматично йдуть ще й на Клубок (klubok.com).
Одна перевірка Картки — для обох сайтів. Темп 10 → 20 → 30 пар/день, спершу зимове.
Дослідження: проєкт Shafa `claude/klubok-analiz-10-11.md`, `claude/klubok-doslid-10-11.md`; сторінки редагування — `~/klubok-4` (не в репо).
Цей файл — `docs/klubok.md` (перенесено в KLB-001; далі його ведуть тікети KLB-002…005).

## Рішення Власника (10.11)
1. Піврозмір → **обидва** цілі (38,5 → 38 і 39).
2. Пост зник з каналу → оголошення в список **«Схоже, продано»**; лише після «Так, продано» Вікторії програма знімає його з Клубку і більше не оновлює. Без підтвердження — нічого.
3. Зміна ціни/тексту в каналі після публікації на Клубку — **не чіпаємо**.
4. З дня запуску Вікторія сама на Клубок не виставляє (дату — при запуску).

## Принципи
- **Шафа не змінюється.** `items.status` — лише Шафа. Клубок має **свою таблицю** зі своїм станом і id.
- **Без ШІ.** Поля Клубку рахує код з Картки (вона вже перевірена) і тексту поста.
- **Захист як у Шафи:** свій `guard` (клік, мережа), квиток на одну публікацію, підставний Клубок для тренувань. **На Клубку небезпечні дії — GET-посилання** (`/renew/all`, `?pg=renew-used`, `?pg=marksold`): guard блокує їх і для GET; навігація — лише за списком адрес.
- **Робот Клубку — окремий профіль Chrome** (`<дані>/klubok-profile/`), але **той самий замок** `robot.lock`: ніколи два Chrome одночасно (слабкий ноутбук).

## Що в Картці → що на Клубку (код, `src/shafa/klubok/fields.py`)
| Клубок | Звідки |
|---|---|
| Название (`item_name`, ≤ 100) | `title` Картки (формат той самий: «… N розміру в … стані») |
| Описание (`text`) | перше речення поста (без ціни) + порожній рядок + `description` Картки (її правки діють) |
| Стоимость | ціна **з поста** (`rules.price_from_text`), не ціна Шафи |
| Категорія (3–4 рівні) | таблиця «група + тип Шафи + сезон → шлях Клубку» (`klubok/category.py`), id — зі знімка |
| Пол (`sex`) | лише дитячі категорії (у дорослих поля немає): `rules.said_gender` — дівчинка 0, хлопчик 1, інакше 2 «Любой пол» |
| Состояние | «Новий» → 1 «Новое», інакше 0 «Б/у». «Сток» — ніколи |
| Размер (`size[]`) | цілі; піврозмір → обидва; значення мають бути в списку розмірів категорії |
| Цвет | перший колір Картки за таблицею UA → ключ Клубку; «Різнокольоровий» або ≥ 3 → 99; немає відповідника → не ставимо |
| Бренд | `brand` Картки; з підказки Клубку — пункт «Бренд (Кирилиця)», чий початок = бренд; немає — вільний текст (живу поведінку перевіряє KLB-003) |
| Фото | порядок Картки, ≤ 15, **по одному**, кожне після завершення попереднього; звірка порядку з `formData.images` |
| Характеристики, доставка, служби | не чіпаємо (за замовчуванням, як у неї) |

Чого не вистачає → Картка на Клубок не йде, причина-код (`klubok_no_category`, `klubok_size`, `klubok_no_price`, `klubok_title_long`). Шафи це не зачіпає.

## Черга й ліміт (KLB-002, зроблено — `src/shafa/klubok/queue.py`)
- **Кандидат:** `items.status` `approved`/`published`, не очищений архів, пост > `SHAFA_KLUBOK_FROM_POST` (типово 7200), рядка `klubok_ads` немає або він `queued`/`skipped` (крім її «Так, дубль»). `publishing`/`problem` Шафи — ні.
- **Вердикт** (`plan` — нічого не пише; `sync` — пише, чіпає лише `queued`/`skipped`, рядки Карток, що вже не кандидати, видаляє; «Скасувати схвалення» прибирає `queued` одразу): `skipped` з кодом `fields.ad` (`klubok_no_category`, `klubok_size`, `klubok_no_price`, `klubok_title_long`, `klubok_no_title`, `klubok_no_photos`), `klubok_post_gone` (нічна перевірка: пост зник, `publish.known_gone`), `klubok_post_done` (інша Картка поста, не сестра-розмір, уже `publishing`/`published`/`sold_asked`/`sold`/`removed` чи `problem klubok_uncertain`); `problem klubok_duplicate` (нижче); інакше `queued`.
- **Порядок:** зимове (сезон містить «Зима»; порожній — з тексту) → інше → лише «Літо»; усередині — старіші пости (`posts.date`, далі `items.id`).
- **Ліміт доби** `SHAFA_KLUBOK_DAILY_LIMIT` (типово 10, 1–30): спроби за місцеву добу за `klubok_ads.publish_started_at` — спільна `publish.started_on` (та сама, що й у Шафи). Ліміти незалежні. Спроба, що повернулась у чергу (`release`), лишається в ліміті; якщо ту саму Картку запустити знову того ж дня, `start` перезапише час — дві спроби однієї Картки за добу рахуються як одна (похибка ≤ 1 на добу, KLB-003 DRIFT-3).
- **`take(conn, root, today, post_id=None)`** → `Taken(cards, code)`: порожньо з причиною, коли Клубок вимкнено (`SHAFA_KLUBOK`, типово ні), знімка її оголошень немає чи він старший за 24 год (`klubok_snapshot_old`), ліміт вичерпано, у черзі нічого (`klubok_queue_empty`); інакше `sync` і по порядку до ліміту, кожна Картка ще раз перевіряється на дубль перед видачею. `post_id` — лише Картки цього поста (фільтр до обрізання за лімітом).
- **Стани:** `start` (`queued → publishing`, `publish_started_at`, `session_id`), `release` (`publishing → queued`: запит публікації точно не пішов; `publish_started_at` лишається), `published` (`klubok_id`, `url` — може бути NULL, його допише знімок), `problem`, `recover` (`publishing → problem klubok_uncertain` «Перевірте на Клубку, чи опубліковано», повтору немає) — кожен в одній транзакції з умовою на поточний стан.
- **Місце в черзі** (`place`, KLB-003 D7): лише рядки `queued`, порядок як у `plan`, без пошуку дублів, без `fields.ad` і без запису (на синтетиці 1787 оголошень × 48 у черзі — ≈ 7 мс замість ≈ 0,3 с). Картка без рядка — «у черзі» без номера.
- **Дублі** (`src/shafa/klubok/dup.py`): її активні (`klubok_listings`, `sold = 0`) і виставлені програмою (`klubok_ads` `publishing`/`published`). Правило — `listings.similar`/`sizes_close`/`prices_close`: розміри оголошення — з назви («38,5 розміру», «27-28 розміру», «40,5 размера»), бренд — `brand` рядка, а якщо NULL — бренд Картки (без уточнення в дужках, лише літери й цифри) **міститься в назві**; **KLB-010:** у назвах обох є номер моделі (цифри токена, не розмір, не рік, не устілка/ціна: «237», «530», «gel-1130» = «1130») і вони різні — не дубль; Картка без бренду — дубль лише при тому самому підтипі (рюкзаки / сумки / гаманці / клатчі / черевики / чоботи / кросівки / туфлі / тапочки…, `dup.subtype`) і ціні ±25 % (з брендом — ±40 %, як було); «нові» ≈ «в ідеальному стані» і 38,5 ≈ 38 не звужуються (на копії 12.11 повний перерахунок: 161 → 160 дублів з 394 Карток Шафи — решту вирішує людина в рядку «Проблем»); категорія — лише коли `category_id` відомий (перший рівень Женское/Мужское/Детское); невідоме не перешкоджає (сумнів — Проблема). Сестри-розміри поста й оголошення Карток того самого поста — не дублі. Кириличних назв брендів у знімку Шафи немає. Рішення на Картці: «Інша пара — виставити» → `dup_ok_at`, `queued`, дублі більше не перевіряються; «Так, дубль — не виставляти» → `skipped klubok_dup_yes` (назавжди), її оголошенню без поста — `post_id` Картки.
- **Фото** (`folders.photo_folder`): `item_folder`, а для опублікованого на Шафі — `<Головна>/Опубліковано/<папка>`. `purge_published` і `borh.purge_photos` не стирають фото поста, поки `queue.needs_photos`: рядок `queued`/`publishing`/`problem` або кандидат без рядка — **незалежно від `SHAFA_KLUBOK`**. Уже стерті — `skipped klubok_no_photos` (TD-070: брати фото з оголошення на Шафі).
- **Стать дитячого:** розділ Картки («Для дівчаток» 0, «Для хлопчиків» 1), інакше слово в тексті, інакше 2.
- **Екран:** на Картці рядок «Клубок: у черзі · місце N / не піде: … / публікується / виставлено ДД.ММ.РРРР · Відкрити на Клубку / Проблема: …» (коли Клубок увімкнено або рядок уже є; GET нічого не пише), для дубля — назва й посилання схожого і дві кнопки; над Проблемами — «Клубок: Проблеми» (лічильник вкладки — лише Шафа). Налаштування — блок «Клубок».
- **Пробний прогін:** `python -m shafa klubok-queue --db <копія> --root <Головна> [--today РРРР-ММ-ДД]` — файл `mode=ro`, копія в пам'яті мігрує, файл не змінюється; ≤ 60 рядків.

Справжній запис — лише зі свіжим знімком (≤ 24 год). `--dry-run` — копія бази в пам'яті, файл і диск не змінюються; звіт ≤ 60 рядків.

Кінець: `ended_at`, `stop_code`, `stop_reason`, `published`, `problems`; звіт у термінал ≤ 15 рядків; гучна подія `klubok.stop` для `klubok_captcha`, `klubok_uncertain`, `klubok_login`, `klubok_429`, `klubok_snapshot_*`, `klubok_forbidden`, `klubok_error`; тиха `klubok.end` інакше.

Що саме кличе reCAPTCHA наживо — видно в списку заблокованого (HYP-3). Без прихованих хитрощів проти виявлення автоматизації: якщо reCAPTCHA не пускає й з `--human-click` — рішення Власника.

### Перша жива публікація 11.11 (KLB-007)

Сесія 62, `--human-click`, пост 7233: Клубок створив оголошення 37977926 — назва, розміри 37 і 38 (піврозмір → обидва), стан б/у, категорія «Женские зимние ботинки», ціна 1900 — усе правильно. Підтвердилось: reCAPTCHA v3 пропустила людський клік; бренд, якого немає в довіднику Клубку (Dachstein), іде вільним текстом. Знахідки: у відповіді `add-edit-used` `used_id` прийшов **рядком** — `_parse` приймає тепер число чи рядок лише з цифр (> 0; `bool` і решта — невпевнено, у журнал сесії йдуть тип і значення `used_id` та перші 300 символів відповіді); вікно Chrome з `viewport 1400×1000` було вищим за екран ноутбука — `LiveSession` відкривається з `no_viewport` (розмір вікна = вікно Chrome).

`python -m shafa robot --klubok-confirm --db … --post P --klubok-id N` — людина підтверджує, що невпевнена публікація відбулась (лише база, Клубок не чіпається; не під час живої сесії робота). Умови: одна Картка поста P у `problem` з кодом `klubok_uncertain`; оголошення N є в знімку (`sold = 0`), не прив'язане до іншої Картки; знімок не старший за добу (інакше «спершу `--klubok-snapshot`»). Результат: `published`, `klubok_id`, `url` зі знімка, `published_at` = зараз, `problem_*` порожні — одним UPDATE з умовою на стан; відмова — база не змінюється.

## Екран: вкладка «Клубок» (KLB-009, KLB-010 — `web.py`, `klubok/screen.py`, `klubok/refresh.py`, `robot/klubok_control.py`)
**KLB-010: де функція та сама — вигляд той самий, що в Шафи.** Шапка в один рядок на 1440 і 1024 (обидва сайти; «Ще не заповнені ШІ» — у «Ще» Шафи); телефон — без горизонтальної прокрутки.
- **Перемикач угорі «Шафа | Клубок»** (`base.html`). Вкладки Клубку — ті самі слова й порядок, що в Шафи (адреси лишились): **«На перевірку»** (`/klubok/review`, Картки «лише Клубок» у `review`) · **«Схвалені»** (`/klubok/queue`, рядки `queued` у порядку черги, мітка «№ N») · **«Проблеми»** (`/klubok/decide`, `problem`) · **«Опубліковані»** (`/klubok/published`) · **«Ще ▸ Сесії»** (`/klubok/sessions`, сесії `site = 'klubok'`, вигляд Шафи, `/klubok/session/N`) · **«Ще ▸ Архів»** (`/klubok/archive`: `skipped` + Картки «лише Клубок» в Архіві — «Не виставляти», «не для Клубку»; групи за причиною; стара `/klubok/skipped` → сюди) · «Ще ▸ Налаштування».

- **Черга завжди актуальна** (кнопки «Перерахувати чергу» й «+N» немає): `klubok/refresh.py` — `reclassify` (хвилі за поточними правилами) + `queue.sync` після `klubok-import`, знімка (`--klubok-snapshot`), кінця сесії робота, на старті `app`/`ui` і після збереження Налаштувань — у фоні (`refresh.Background`, ≈ 2,5 с на копії 12.11), не в GET; «Схвалити»/«Не виставляти» — `sync_one` цієї Картки. Лічильник «Схвалені» — одне число.
- **Картка** `/klubok/item/N` (`card.html`, `site = "klubok"`) — каркас Шафи: верх «← список · 3 з 8 · Назад / Далі» + стан «Робот · ШІ · Бот» (на 390 — 2 рядки, обидва сайти); фото ліворуч, поля праворуч на першому екрані; **«Як буде на Клубку»** — компактно у правій колонці над полями (`klubok_view.html`; на телефоні згорнуто: «▸ Як буде на Клубку: Демисезонные ботинки · 37 · 650 грн»); що заважає схвалити — **одна причина одним реченням** («Щоб схвалити: вкажіть розділ» / «Схвалити не можна: у пості немає ціни»), кнопка неактивна; кнопки — **«Попросити ШІ заповнити заново · Ще · Не виставляти (в Архів) · Зберегти · Схвалити і далі»**.

- Сторінка помилки (404/403/500) — з шапкою (обидва сайти). Фото, що не завантажилось, — заглушка «немає фото» (`app.js`).

## Дублі за фото (KLB-011 — `klubok/dupcheck.py`, `klubok/photo_dup.py`)
Правило за текстом (`klubok/dup.py`) лише знаходить кандидатів; вирішує програма, людина — лише коли не змогла.
- **Коли:** `refresh.Background` після `queue.sync` (той самий потік, екран не чекає; ≤ 40 запитів ШІ за прохід) і CLI `klubok-dups [--dry-run] [--no-ai] [--limit N]`. Беруться `problem klubok_duplicate` без маркера в `problem_text` («Фото не порівняно: …», «ШІ не впевнений: …», «ШІ не порівняв: …»). Кандидати — `dup.find_all` щоразу заново (знімок міг змінитись); `find` = перший з них.
- **Фото:** dHash 64 біти. Її мініатюра в знімку — 158×158, центральний квадрат фото, тому наше фото теж обрізаємо до квадрата. Наші — усі фото Картки (≤ 15) + фото поста з Експорту; виставлене програмою — фото тієї Картки. Відстань ≤ **T1 = 4** → дубль. Виміряно на копії 12.11: 11 з 84 на відстані 0–1 (усі — через фото поста з Експорту), у 19 050 чужих парах мінімум 6. Більша відстань нічого не доводить.
- **ШІ:** `dup.Judge(site="klubok")` — інструкція `prompts/duplicate-klubok.md`, ціна з поста, без факту про інший пост; наше фото — найближче за відбитком, її — велике `/l/` (1024×768, адреса з `/m/` лише за точним шаблоном; не вийшло — мініатюра).
- **Рішення:** хоч один дубль (фото чи ШІ `yes`) → `skipped klubok_dup_yes`, текст «Дубль — …», її оголошення знає пост; усі `no` → у чергу як «Інша пара» (`dup_ok_at`, текст «Інша пара — ШІ: …» живе після `sync`); кандидатів немає → «Інша пара — схожого на Клубку вже немає»; > 3 кандидатів чи оголошення програми ще публікується → людині без ШІ (збіг фото — однаково дубль); інакше людині зі словами ШІ.
- **Тимчасове** (мережа, 5xx, бюджет ШІ, немає ключа, ліміт запитів) — без маркера, наступного разу знову. **429/403** від `img.klubok.com` — стоп проходу (подія `klubok.dup_stop`). Фото — лише `https://img.klubok.com/`, GET без cookies, ≤ 5 МБ, `image/*`, пауза 0,5–1 с, кеш `<дані>/klubok-photos/`.
- **Слід і відкат:** тиха подія `klubok.dup_auto`; «Ще ▸ Архів» — група «Дубль — вирішила програма» з посиланням на її оголошення й кнопкою «Ні, це інша пара — виставити» (`queue.undo_auto_dup`); «Схвалені» — мітка «Інша пара (ШІ)»; над «Проблемами» — «Програма вирішила: X дублів, Y інших пар · вам лишилось Z».
