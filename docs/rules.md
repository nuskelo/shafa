## 1. Вхід

- **Папка товару:** назва `^\d+$`. Якщо довжина > 10 і починається з `2394827824` — номер поста = решта цифр; інакше вся назва = номер поста.
- **Фото:** лише `.jpg/.jpeg` (без урахування регістру), ≤ 10 шт., кожне ≤ 10 МБ. Поворот брати з EXIF (orientation). Пропорції 4:3 і 3:4 (±2%) — норма; інші → «Проблеми».
- **Текст поста:** Етап 1 — з `result.json` (поле `text` може бути рядком або списком шматків). Етап 2 — з повідомлення Боту.
- **Старі пости (v1.3):** без папки, з Експорту з фото — `import-old` за списком номерів. Фото одне — з поля `photo` поста, копіюється в теку даних програми (`borh/<номер>/1.jpg`). Немає фото → «Проблеми» («У пості немає фото»). Пост уже є в базі (папка, бот, попередній імпорт) — пропускається; папка в Головній для поста, завантаженого як старий, → «Проблеми».
- Пост без ціни або без поста з таким номером → «Проблеми».
- Пост із кількома товарами (кілька рядків, кожен зі своєю ціною) → «Проблеми» (`many_items`).
- **(v1.4)** Два й більше різних розміри в пості («43 і 45», «розміри 37 та 38», «38 … є ще 40») → «Проблеми» (`many_items`), до ШІ. Не рахуються: діапазон «38-39», «вказаний X, ідуть на Y», розпаровка (лівий/правий), розміри ближче 0,5. **(v1.6)** Рахуються: «(де)кілька розмірів» / «різні розміри» і два різні «вказаний X» в одному пості. Ці перевірки тексту робить і «Перезаповнити»: Картка, завантажена до нових правил, іде в «Проблеми» без ШІ.

## 2. Ціна (код)

```
p = ціна_з_тексту * 1.15          # остання «NNNгрн» / «NNN грн» / «NNNгр.» у тексті, закреслені не рахуються
p = ceil(p / 10) * 10             # вгору до десятка
if 450 <= p <= 500:  p = 501
if 950 <= p <= 1000: p = 1001
```
Приклади: 600→690; 655→760; 420→490→501; 850→980→1001; 1200→1380.
Дві ціни (стара закреслена + нова) → нова (остання). Рахувати в цілих числах, без float.

## 3. Очищення опису (код)

Прибрати: перше речення (воно = назва; кінчається на перший перенос рядка або `.`/`!`/`?` з пробілом після; крапка в скороченнях `Dr.`, `р.`, `см.`, `т.д.` — не кінець), ціну (`\d+\s*гр(н)?\.?`), підпис `Пишіть сюди 👉 @viktoriaviktoriatg`, будь-які `@нікнейми`, посилання, телефони, хештеги (`#VS_42_розмір`). Додати в кінець: «Ідеальний стан, без дефектів.» (стан Ідеальний) або «Стан нових, без дефектів.» (стан Новий), якщо в тексті вже немає речення про стан.

## 4. Стан (код)

Усі форми слова «нов-» як ціле слово («новий», «нові», «нова», «нової», «в стані нових/нового», «в новому стані») → **Новий**; інакше → **Ідеальний**. «Нова пошта», «новорічні», «нова колекція» — не стан.

## 5. Назва (ШІ, код перевіряє довжину й відсутність контактів)

`[Нові] [Шкіряні/Замшеві] [термо] <тип> <бренд> [модель] [оригінал] [з мембраною gore-tex] <N> розміру [в ідеальному стані / у відмінному стані / в стані нових]`
Без статі й кольору. ≈ перше речення поста + розмір. Приклади з її профілю: «Шкіряні черевики pavers 42 розміру», «Кросівки adidas оригінал в ідеальному стані 44 розмір», «Зимові термо черевики lowa з мембраною gore-tex 37 розміру в ідеальному стані», «Шкіряна сумка caroll paris в новому стані».

## 6. Розділ (ШІ за фото + розміром; код перевіряє, що шлях є в дереві Шафи)

- Взуття: `Жіночий одяг / Взуття / <тип>`, `Чоловічий одяг / Взуття / <тип>`, `Дитячий одяг / Для дівчаток | Для хлопчиків | Для малюків / Взуття / <тип>`.
- Сумки/рюкзаки/гаманці/ремені: `Аксесуари / Сумки та рюкзаки | Гаманці та портмоне | Ремені та пояси / <тип>` + поле «Стать: Для жінок».
- **Група (v1.4, код поверх ШІ):** слово в тексті («жіночі», «чоловічі», «для дівчинки», «для хлопчика») важливіше за розмір; «унісекс» або обидва слова — як без слова. Без слова: ≤ 22 — «Для малюків» (23 і більше — **ніколи**, схвалити не можна); 23–34 — дитяче, стать дитини не сказано → жовте з підказкою; **(v1.5)** 35–39 і в тексті немає дитячих слів («дитячі», «для дівчинки/хлопчика», «підліт…», «шкільн…») → жіноче, не жовте, «Категорія» (teen) не жовта (у дорослому її немає) — пілот 18.10: ШІ ставило 36–37 у «Для дівчаток» (6 з 43); з дитячими словами 35–36 — як у v1.4: ознаки дорослого (каблук, «жіночі») → жіноче, інакше жовте; доросле ≤ 39 → жіноче; **(v1.7)** 40 → жіноче, не жовте (у її оголошеннях 40 — 84 % жіночі); чоловіче — лише «чоловічі» в тексті або ШІ бачить явні чоловічі ознаки (модель/лінійка), жовте — лише коли ознаки суперечать; 41–42 — вирішує ШІ (фото, бренд, модель), жовте лише при сумніві ШІ; ≥ 43 → чоловіче. **(v1.7)** 35–36 з ознаками дитячої лінійки (Kids, Junior, Jr, «J» після моделі, «дитячі») чи дитячими ознаками на фото (ШІ: «можливо дитяча модель») і без ознак дорослого → жіноче, але **жовте** «можливо дитяча модель — перевір»; без ознак — жіноче, не жовте. Код переносить розділ у потрібну групу з тим самим типом; такого типу там немає — жовте. Групу вирішив код — сумнів ШІ про стать не рахується (про тип — рахується).
- **Тип (v1.4):** «сапожки» → Чоботи; «Дутики» — лише якщо так у тексті, інакше жовте. **(v1.6)** «уги/угги» → Уггі; слово типу — лише з першого речення («Висота сапожка 13 см» у замірах угів — не тип).
- Невпевненість → жовта позначка. **Розділ після публікації не змінюється.**

## 7. Розмір (код+ШІ)

Система «Європейський» (малюки — «Український» 15–22 + обов'язкова «Стать»). Шафа вимагає: **розмір в оголошенні = розмір на ярлику** — крім «вказаний X, ідуть на Y» (v1.7, рішення Власника: Y).
- **(v1.7, рішення Власника 18.10)** «Вказаний X, ідуть на Y» → поле «Розмір» = **Y** («ідуть на») — і вживане, і нове (так вона ставить сама, 1405). Назва — «Y розміру», в описі лишається «Вказаний X розмір. Ідуть на Y» (текст поста, опис не міняється). До v1.7: вживане — X і Y, нове — X.
- **(v1.4)** «Вказаний X / на ярлику X, ідуть на Y» застосовує код → не жовте. Один розмір у тексті й ШІ дало його ж — сумнів ШІ не рахується. Розпаровка — жовте.
- **(v1.6)** Ярлик не європейський («вказаний розмір 5 / 6,5 / 12», X < 15), «ідуть на Y» — європейський → поле «Розмір» = **[Y]** (і вживане, і нове), група — за Y, не жовте. UK це чи US, з тексту не видно, а на Шафі лише європейська; так вона й ставить (пілот: 59 таких постів з 962). Обидва не європейські («9,5 US, ідуть на 10 US») — таблиця US/UK, як у v1.3. Розмір < 15 ніколи не «Для малюків».
- Списки розмірів — явні, зі знімка форми Шафи (`shafa-catalog.json`), не межі+крок.
- **Лише європейська система (v1.3).** Розмір у тексті в US чи UK (і європейського немає) — ШІ повертає число як у тексті й систему (`size_system`), переводить **код** таблицею (`src/shafa/sizes.py`, окремо жіноча / чоловіча / дитяча; джерело — у коді). Немає групи (розділ невідомий, малюки, аксесуари), розміру немає в таблиці або таблиця дає діапазон («US 8 → EU 38–39») → жовте поле з причиною. Правило «вказаний X, ідуть на Y» лишається (обидва переводяться).

## 8. Колір (ШІ)

1–2 з 32 варіантів Шафи, першим — головний (колір верху); дрібні деталі (шнурки, підошва, підкладка) не рахуються; 3+ помітних кольори верху → «Різнокольоровий». **v1.4:** більше двох — код лишає перші два; відтінок — найближчий з довідника; сумнів ШІ про колір жовтим не робить.

## 9. Матеріали, мембрана, устілка, додаткові поля

| Поле | Хто | Правило |
|---|---|---|
| Матеріал (верху) | ШІ + код | **v1.3:** лише Шкіра / Замша / Нубук і лише якщо названі в тексті; кілька → кілька («шкіра і нубук» → Шкіра + Нубук). Будь-який інший (текстиль, сітка, штучна шкіра…) → поле порожнє (код відкидає). «Шкіра», а в тексті є «штучна шкіра» / «екошкіра» → жовте |
| Матеріал підкладки | ШІ + код | Лише названа в тексті. **v1.4:** синоніми → значення довідника типу («натуральне хутро» / «хутро» → Хутро або Натуральне хутро, «фліс» → Фліс, «текстиль» → Текстиль, «шкіра» → Шкіра; **v1.6:** «шерсть» → Вовна); не з тексту або немає в довіднику типу → поле порожнє, **не жовте** |
| Мембрана | код | `gore-tex` → «Gore-Tex»; будь-яка інша мембрана → «Є»; немає → не заповнювати |
| Довжина устілки | код | Усі заміри **довжини** з тексту (у т.ч. «до згину на п'ятку A, від краю до краю B»); **«Ширина устілки» — пропускати**. Значення не на кроці 0,5 (25,8) → обидва сусіди сітки (25,5 і 26). Потім усі значення з кроком 0,5 між мін і макс; одиночне X,5 → X і X,5 (як у неї). Діапазон перевіряє код розділу (дорослі 22,5–31; дитячі менші) |
| Сезон | код, інакше ШІ | **v1.4:** названо прямо — як у тексті; «термо», «хутро» / «на хутрі» (не «без хутра»), «утеплені», «зимові», «уги/угги», «дутики», «на флісі» / **(v1.6)** «всередині фліс» (не «мікрофліс», не «без флісу») → Зима; мембрана / Gore-Tex / «не промокають» без ознак зими → Демісезон; жовте лише коли текст суперечить сам собі («літні … на хутрі»). Текст мовчить — ШІ, лише коли очевидно, без жовтого |
| Стиль / Тип / Категорія «Для підлітків» | ШІ | Лише коли очевидно. «Челсі» — лише з гумовими вставками з боків. **v1.6:** поля немає в типу розділу (стиль у кросівок) — код лишає порожнім, не жовте |
| Бренд | ШІ | Із тексту, зі списку Шафи. Немає в списку → жовта позначка (правило — відкрите питання) |
| Ключові слова | ШІ | 4–6: тип; тип+стать; тип+бренд; тип+розмір; за потреби сезон або яскравий колір |

## 10. Фото (код+ШІ)

Порядок = порядок імен файлів у папці (у неї головне вже перше, бірки останні). ШІ перевіряє: перше — взуття боком, носком вліво (сумки — файл «1» або фото спереду); фото бірок — у кінці (може бути 2). Інакше — переставити і жовта позначка. **v1.4:** одне фото (старі пости) — ніколи не жовте.

## 11. Нові правила для готових бланків (v1.7, CORE-009)

- Відповідь ШІ зберігається як є. Змінились лише правила коду — «Перерахувати правилами» (і сама на старті нової версії програми): поточні правила до збереженої відповіді, тексту поста і її правок; ШІ не викликається, правки не чіпаються. Бланкам до CORE-009 відповідь зібрано з бланка.
- Змінилась інструкція ШІ — ярлик «заповнено старими правилами» і «Перезаповнити (N)» лише на Картках, де нова інструкція могла змінити відповідь (v1.6: «Челсі», слова назви не з тексту, сумнів про мембрану чи стать 41–42; v1.7: 35–36 без ознак дорослого, 40 у чоловічому).
- Розділ без місця на Шафі (`no_section`) — розмір не жовтий; розпаровка — одна причина «лівий і правий різні — перевір розмір».
