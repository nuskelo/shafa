# BOT-011 — кнопки під тривогами: вирішувати Проблеми прямо в Telegram

**Вага:** середня (~1 год). **Рішення Власника (21.10):** «щоб у тому боті можна було зразу вирішувати щось». Схвалення Карток у бот НЕ переносимо (там не видно бланка) — лише на екрані.
**Аналоги:** BOT-010 `bot/alerts.py` (тривога про нову Проблему), `bot/core.py` `_callback` (кнопки чернеток: `дія:id`), `web.py` ~рядки 970–1000 (гілки «Перевірити ще раз» за `problem_code`: `photos_missing`, `robot_*`, `STALE_RULES`, `STICKY`, решта), `review.act` (В архів, дубль/не дубль).

## Навіщо
Тривога «⚠️ Пост N: …» приходить у Telegram, але щоб її вирішити, треба AnyDesk і екран програми. Найчастіші рішення — в одну кнопку.

## Що зробити
1. **Спільна логіка:** винеси гілки «Перевірити ще раз» з `web.py` в одну функцію (напр. `review.recheck(conn, item_id, root) -> (статус, повідомлення)`), `web.py` викликає її — поведінка екрана не змінюється (наявні тести web мають лишитись зеленими без правок).
2. **Кнопки під тривогою про Проблему** (по одній Картці; якщо в одному повідомленні кілька — кнопки для перших 5, решта «Відкрийте програму»):
   - «🔁 Перевірити ще раз» → `review.recheck`; відповідь у тому самому повідомленні: «Пост N → На перевірку / Схвалені / досі Проблема: …».
   - «🗄 В архів» → те саме, що кнопка на екрані; **підтвердження** другою кнопкою «Так, в архів» (одна випадкова кнопка нічого не ламає).
   - Для `possible_duplicate`: фото нашої Картки + фото «схожої» з Шафи (`duplicate_url`/`my_listings.photo`) одним альбомом, кнопки «✅ Різні пари» (→ як на екрані «не дубль») і «🗄 Дубль» (→ Архів `duplicate`).
   - `shafa_declined`: «🔗 Відкрити на Шафі» (посилання) і «🗄 В архів».
3. **Тривога про зупинку робота:** кнопка «📋 Що сталось» → короткий текст останніх Проблем сесії. **Без кнопки «Старт»** (робот стартує лише з екрана).
4. **Безпека:**
   - Кнопки працюють лише для `TELEGRAM_OWNER_CHAT_ID` (і від цього користувача); інші — «Немає доступу», нічого не змінюється.
   - Перед дією перевірити, що Картка досі в тому самому стані/`problem_code`, що був у тривозі (у `callback_data` — id Картки + короткий код стану). Змінилась (вже вирішили на екрані) → «Уже вирішено», нічого не робити.
   - Жодна кнопка не робить Картку `approved` в обхід правил: «Перевірити ще раз» — лише те, що робить екран (для `photos_missing` → «На перевірку» тощо).
   - Картки з `shafa_id` — ніяких дій, крім «В архів» для `shafa_declined`.
   - Поки працює робот (сесія відкрита) — дії над Карткою в черзі робота (`publishing`) заборонені: «Робот зараз працює з цією Карткою».
5. Після натискання кнопки прибрати (`editMessageReplyMarkup`), щоб не натиснути вдруге; результат дописати в повідомлення.
6. `CLAUDE.md`.

## Гіпотези (Фаза 0)
- HYP-1: `callback_data` ≤ 64 байти вміщує `дія:id:код` (Telegram-ліміт).
- HYP-2: `review.act` уже вміє «В архів», «не дубль», «дубль» без `web.py`.
- HYP-3: бот і програма можуть одночасно писати в базу (WAL / тайм-аут) — перевір, як уже пишуть бот і екран.

## Заборони
Живу Шафу не відкривати. Канали, сайт, `.env` — не чіпати. `robot/*`, `db.py`, `health.py` — не змінювати. Поведінка екрана не змінюється. Справжніх запитів до Telegram, ШІ, сайту в тестах не робити. Вивід обрізай (`| tail -n 40`).

## Тести
Кожна кнопка → той самий результат, що на екрані; чужий користувач → нічого; Картку вже вирішено → «Уже вирішено»; «В архів» без підтвердження нічого не робить; `possible_duplicate` → альбом + 2 кнопки; Картка з `shafa_id` — лише `shafa_declined` «В архів»; після натискання кнопки зникають; наявні тести `web` зелені без змін.
