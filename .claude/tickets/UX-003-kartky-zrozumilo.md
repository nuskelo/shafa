# UX-003 — Картки: черга «На перевірку», жовтий розділ, ціна, схвалені

Вага: велика · Модель: Sonnet · High · Аналоги: UX-001/UX-002 (PR #79, #80), UI-007 (кнопка «Далі →»). Дизайн НЕ міняти — лише тексти і поведінка (нові кнопки — існуючими класами).

## Навіщо
Програма переходить до Вікторії (не технічна, працює сама). UX-аудит 31.10 (копія на 081843a з базою пілоту). Вона має пройти чергу від першої до останньої Картки і ЗАВЖДИ знати, що лишилось і що робити далі.

## Баги (спершу)
- **B1 Кінець черги бреше.** Пропустила Картку «Далі →», схвалила решту → «Схвалено. Усе переглянуто — більше Карток у цьому списку немає», а пропущена лишилась (web.py:1199-1203, :92-94). Треба: 0 лишилось → `Схвалено. На перевірці більше нічого немає — можна натискати «Старт» угорі.`; >0 → `Схвалено. Лишилось N пропущених — ось перша з них.` і перехід на першу пропущену (по колу).
- **B2 Фільтр.** На `f=warn` у кінці: «Усе переглянуто» + «У цьому фільтрі нічого немає», хоча в «Готові · 4» 4 Картки не схвалені (web.py:92, :1055-1056; list.html:41) → `Жовтих більше немає. Ще 4 Картки без жовтого чекають на «Схвалити» → [Переглянути їх]`. Фільтр «Готові» → `Без жовтого`.
- **B6 Неправдива помилка.** Розділ заповнено, а під ним червоне «обов'язкове поле — без нього не схвалити» на кожній Картці з жовтим розділом (web.py:1446-1449; card.html:86). `section_yellow`/`section_unknown` — НЕ «порожнє поле»; червоний «обов'язкове» — лише для порожнього.

## Рішення Влада: кнопки «Жіночі / Чоловічі» (B7)
Найчастіше жовте поле (15 з 17 жовтих Карток у пілоті) — розділ, де ШІ не впевнений жіноче/чоловіче. Зараз: «Перевір 1 поле: Розділ» + довгий абзац ШІ; змінити можна лише надрукувавши шлях «Чоловічий одяг / Взуття / …» (ai.py:781, :451-452; card.html:87-90).
Зробити:
- Заголовок жовтого розділу: `Перевір: жіночі чи чоловічі?`. Причину ШІ — перше речення; повністю — під «Чому?».
- Дві кнопки біля поля: `Це жіночі` / `Це чоловічі` — міняють лише верхню групу розділу (Жіночий одяг ↔ Чоловічий одяг), решту шляху (Взуття / Кросівки…) лишають; якщо такого шляху в іншій групі нема в `shafa-catalog.json` — кнопку не показувати (не вигадувати розділ). Натискання = поле змінено людиною (жовте знімається, як після ручної правки). Для дитячих розділів — `Для дівчаток / Для хлопчиків`, якщо шлях існує.
- Кнопка «Так, вірно» лишається.
- Правила розміру (≤39/40 жіноче, ≥43 чоловіче, 41–42 — дивиться людина) НЕ міняти — це лише зручний спосіб змінити поле.

## Тексти і поведінка
1. **B8 Ціна поза межами.** 5 і 99999 грн при пості 1500 — зберігаються мовчки (review.py:107-112). Відхилення >30 % від «ціна поста ×1,15» → поле жовте: `Ціна 5 грн дуже відрізняється від поста (1500 грн → на Шафі 1730). Перевір.` + «Так, вірно». Формулу ціни НЕ міняти.
2. **B9** Приймати `1 960`, `1960 грн` (пробіли, «грн»); помилкове значення лишати в полі з текстом `Ціна — лише цифри, напр. 1960`.
3. **B12** «Скасувати схвалення» → лишатися на тій самій Картці з полями для правки: `Схвалення скасовано — можна правити. Потім знову «Схвалити».` (зараз відкриває список, web.py:1203).
4. **B13** На схваленій Картці (сірі поля): `Картку схвалено — правити не можна. Щоб змінити, натисніть «Скасувати схвалення» внизу.`
5. **B15** Після «Так, вірно» під полем «змінено вручну» → `підтверджено вами` (card.html:91-92; review.py:471).
6. **B16** Дві кнопки «ШІ, спробуй ще раз · ≈ 5 ¢» і «Перезаповнити пакетом · ≈ 1,5 ¢» (card.html:315-316) → одна видима `Попросити ШІ заповнити заново`; друга — під «Ще» з поясненням `Дешевше, але результат до години — Картка на цей час зникне зі списку.` Без «¢» (якщо ціна — у форматі `≈ 0,05 $`).
7. **B17/B18** Фільтри: дві «Усі» з різними числами; «Нові (бот)» плутається зі станом взуття «Новий» (web.py:1053-1067; list.html:16-29, :63) → підписи груп `Що треба: Усі / Треба глянути / Без жовтого` і `Звідки: Усі / З бота / Старі пости`; мітка на плитці `З бота · 7 фото` замість «Нова · 7 фото».
8. **B30** 3–4 червоні блоки одночасно (card.html:135-138, :319) → один блок `Щоб схвалити: 1) вкажіть ціну; 2) перевірте розділ` (пункти — з того самого `approve_block`/MISSING).
9. **B31** Порожня ціна → «Зберегти» → «Збережено» → `Збережено, але без ціни Картку не схвалити.` (web.py:1191-1192).
10. **B32** Підказки: «у пості 1700 · +15%» → `У пості 1700 грн → на Шафі +15 % = 1960`; устілка: `Устілка: у пості 25,3 см (на Шафі: 25 і 25,5)` (card.html:83-84).
11. **B33** Заголовок: «Пост 6979 від 2026-10-15 · папка borh-6979» → `Пост 6979 · 15.10.2026`; без назви — `Пост 7027 (назви ще немає)`; слово «borh» і «папка» на екрані не показувати (card.html:118-120; list.html:59).
12. **B34** «Схвалено» на наступній Картці → `Схвалено «<назва>» → у «Схвалених». Це наступна Картка.`
13. **Б5** Наприкінці черги / у «Схвалених»: `Натисніть «Старт» — сьогодні робот опублікує до N із M Схвалених.` (N — та сама функція, що в UX-002 «Опублікує до …»).

## Фаза 0 (HYP — перевір, впиши в handoff)
- HYP-1: «Усе переглянуто» рахує лише Картки після поточної, пропущені «Далі →» не враховує (B1).
- HYP-2: червоне «обов'язкове» береться з MISSING, куди потрапляє `section_yellow` (B6).
- HYP-3: для кожного розділу пілоту (review/approved) парний розділ в іншій групі існує в каталозі — скільки так, скільки ні.

## Тести
- Черга: пропуск + схвалення решти → «Лишилось 1 пропущених», перехід на неї; 0 → «можна натискати «Старт»».
- `f=warn` в кінці → посилання на «Без жовтого».
- Жовтий розділ заповнений → нема «обов'язкове поле».
- «Це чоловічі» на «Жіночий одяг / Взуття / Кросівки» → «Чоловічий одяг / Взуття / Кросівки», жовте знято, «змінено вами»; нема пари в каталозі → кнопки нема.
- Ціна 5 при пості 1500 → жовте; «1 960» приймається.
- «Скасувати схвалення» → та сама Картка, поля активні.
- Немає «¢», «borh», «папка borh» у шаблонах Картки/списку.
- Форми `action/value/name` існуючих кнопок — без змін.
