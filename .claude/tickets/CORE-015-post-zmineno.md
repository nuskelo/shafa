# CORE-015 — Пост або фото змінено після scan (TD-004)

Вага: **Звичайна**. Аналоги: SITE-002 (`edited_channel_post`, `_post_deleted`), CORE-009 B (`fill.recheck` — перерахунок без ШІ), QA-002 (Схвалена зі зміненим бланком → «На перевірку»).

## Навіщо
Вікторія інколи змінює ціну чи текст поста або перезнімає фото вже після того, як програма зробила Картку. Зараз Картка «На перевірку»/«Схвалені» цього не бачить: на Шафу піде стара ціна або робот впаде на зниклому фото (`robot_photos`). Мета — програма сама підхоплює зміни, Власник бачить лише те, що треба перевірити.

## Що зробити
1. **Текст поста змінено** (`Core._channel_edit`, пост нашого каналу, текст справді інший):
   - Оновити `posts.text` (зараз оновлюється лише черга сайту — це лишити як є).
   - Картки цього поста за статусом:
     | Статус | Що робити |
     |---|---|
     | `new`, `problem` (не «липкі») | лише новий текст; ШІ побачить його в наступному пакеті |
     | `review` | перерахувати поля коду (ціна, стан, опис, устілка, мембрана — як `fill.recheck`, **без ШІ**); примітка на Картці «Пост змінено <дата>: <що змінилось, напр. ціна 1200 → 1000>» |
     | `approved` | те саме + повернути «На перевірку» (як QA-002), примітка та сама |
     | `publishing`, `published`, `archived` | статус не міняти; для `published` — рядок у журнал бота і в щоденний звіт (BOT-009) «Пост N змінено після публікації на Шафі: <що>» — на Шафі правимо вручну |
   - Повторне те саме редагування (той самий текст) нічого не робить.
2. **Фото в папці змінено** (TD-004): `scan` для `review`/`approved` звіряє список фото з папкою (назви, кількість; розмір/час файлу — якщо вже десь є такий підпис, інакше лише назви).
   - Змінилось → оновити список фото Картки (мініатюри — як для нових), примітка «Фото змінено <дата>»; `approved` → «На перевірку».
   - Папку видалено / фото не лишилось → Проблема `robot_photos` з людським текстом (не падати).
   - `publishing`/`published`/`archived` — не чіпати.
3. **Пост видалено з каналу** (рішення: видалене = продано): зараз `_post_deleted` перевіряє лише пости бота (`from_bot`). Фаза 0: з'ясувати, **чому** лише бота. Якщо причина лише технічна і `presence` працює для старих постів — розширити на всі. Якщо причина продуктова (старі пости вона не видаляє при продажу, або інше) — **не міняти**, описати у звіті.
4. Екран: примітки п. 1–2 видно на Картці (там, де показуються інші примітки), значок у списку — як для QA-002.
5. Тести: кожен рядок таблиці п. 1; повторне редагування; ціна змінилась → нова ціна Шафи за правилом (·1,15, вгору до десятка); фото додано / прибрано / папку видалено; `published` не змінює статус і пише рядок у звіт; жодного запиту до ШІ при перерахунку.
6. `CLAUDE.md`, `docs/TECH_DEBT.md` (TD-004 закрито або що лишилось).

## Гіпотези (Фаза 0)
- HYP-1: `edited_channel_post` приходить і для старих постів (з Експорту), коли бот працює.
- HYP-2: `fill.recheck` (або його ядро) перераховує поля коду для однієї Картки без ШІ.
- HYP-3: є місце для примітки на Картці (поле чи таблиця), яке не вимагає змін `db.py`. Якщо вимагає — лише `ALTER TABLE … ADD COLUMN`, опиши у звіті.
- HYP-4: `scan` знає список фото Картки і може його порівняти без ШІ.
