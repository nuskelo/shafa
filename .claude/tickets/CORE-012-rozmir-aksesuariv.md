# CORE-012 · Розмір у формі аксесуарів (обов'язковий!) — знімок його не бачить

> Архітектор, 19.10.2026. Після мержу PR #35. Гілка `feature/CORE-012-rozmir-aksesuariv` від свіжого `origin/main`. Першим комітом — тікет, STATUS.md, перенесення `.claude/handoff/CORE-011.md` в архів. Терміново: 7 схвалених карток аксесуарів чекають.

## Що показав живий dry-fill 3650 (рукавички, 19.10 18:01, скриншот `~/shafa-viktoria/robot-screens/20261019-180124-3650.png`)
- У формі «Рукавички» є **обов'язкове** поле **«Виберіть размер \*»** (підпис мішаний UK/RU!) з кнопками: `XS S M L XL 2 3 4 5 6 6.5 7 7.5 8 8.5 9 One Size Інший`, з підказкою «для вживаних — можливі дві опції; для нових — опція має бути не більше, ніж кількість товарів».
- Знімок після sync (CORE-011) для всіх 51 розділу аксесуарів має `sizes: {}` → робот поле не заповнив → «Додати річ» не пройде. Отже `robot/sync.py` цей блок розміру не бачить (інша розмітка/підпис «размер», без перемикача систем EU/UA/US).
- Решта форми — вірно: розділ, Стан, ключові слова, Колір, Стать «Для чоловіків», Сезон «Зима», Матеріал «Шкіра», ціна 350.

## Що зробити
1. `sync.py`: знімати й цей блок розміру (варіанти + обов'язковість), підпис через `lang.py` («Виберіть размер» ↔ «Виберіть розмір»). Поки живого повторного sync нема — вписати варіанти зі скриншота в знімок для розділів, де Архітектор їх бачив (Рукавички), і **позначити в handoff**, що для шарфів/шапок треба живий dry-fill.
2. Правило розміру аксесуарів (рішення Архітектора): літерний розмір з тексту → ці кнопки («S/M» → S і M, бо вживане — до двох; «XL» → XL; «M» → M). У тексті розміру немає → **«Інший»**. Для нових — не більше однієї опції (для «S/M» нових → перша, S, і жовте).
3. Робот: якщо форма має обов'язкове поле, якого план не заповнив, — Проблема до кліку «Додати річ» (зараз dry-fill мовчки пропустив). Перевір, чи є така перевірка; якщо нема — додай (не в `guard.py`).
4. Тести: фальшива форма з цим блоком; S/M → дві; без розміру → «Інший»; новий S/M → одна + жовте; обов'язкове порожнє → Проблема.
