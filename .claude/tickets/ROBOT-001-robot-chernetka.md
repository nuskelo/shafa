## Навіщо
Робот — те, заради чого все будується: схвалену Картку він переносить у форму «Додати товар» на Шафі. У цьому тікеті робот **заповнює форму повністю і зупиняється перед кнопкою «Додати річ»**: скріншот заповненої форми, без публікації. Заодно робот збирає з форми справжні довідники Шафи (TD-006, TD-007), щоб розділи перестали бути жовтими через «не звірено».
Форма — `docs/research/shafa-form.md`. Імпорту з файлу на Шафі немає, API немає.

## Правила безпеки (незмінні)
- **Жодного натискання «Додати річ» / «Опублікувати» / будь-якої кнопки, що створює чи змінює оголошення.** Код має явний захист: кнопку публікації не можна натиснути в цьому тікеті навіть помилково (перевірка тексту/селектора перед кожним кліком + тест).
- Окремий профіль Chrome для робота (не основний профіль Власника). Вхід на Шафу в цей профіль робить **Власник руками** один раз; робот пароль не бачить і не вводить. Профіль лежить **поза репозиторієм** (тека даних програми), `.gitignore`.
- Видимий браузер (не headless) — Власник бачить, що робить робот.
- Темп людини: паузи між діями, без паралельних вкладок, без масових запитів. Один прогін = до 3 Карток.
- Скріншоти й дампи сторінок — поза репозиторієм; у звіт — лише висновки (без особистих даних акаунта).

## Фаза 0 — повністю, зупинка до коду
- HYP-1: **Playwright для Python** — актуальна версія (≥ 14 днів), запуск із власним постійним профілем (`launch_persistent_context`), працює на Mac і Windows; чи можна використати встановлений Chrome замість завантаженого Chromium (на ноутбуці Продавчині Chrome уже є). Залежність — у `[project] dependencies`; браузер для CI не потрібен (тести без мережі).
- HYP-2: **Правила Шафи щодо автоматизації** — що кажуть умови користування / правила для продавців про боти й автоматичне додавання. Цитати й посилання у звіт. Якщо пряма заборона — **стоп**, рішення за Власником.
- HYP-3: **Форма наживо** (акаунт Власника, після його входу в профіль робота; лише читати, нічого не надсилати):
  - як завантажуються фото (input type=file? drag-and-drop? скільки слотів, чи є галочка «фото зроблені самостійно»);
  - як обирається розділ (дерево кліками / пошук), **повне дерево** потрібних розділів: жіноче, чоловіче взуття, дитяче (дівчатка, хлопчики, малюки), сумки/рюкзаки, гаманці, ремені — назви точно як на сайті;
  - поля після вибору розділу для кожного з цих розділів: розміри (системи, діапазони, крок), кольори, матеріали, мембрана, устілка, сезон, стиль, тип, стать для аксесуарів, «Для підлітків»;
  - бренд: пошук зі списку, що буде, якщо бренду нема («Додати бренд: X»);
  - ліміт довжини назви й опису (TD-007), ключові слова (як додаються);
  - чи є чернетки / автозбереження форми (якщо є — це наш безпечний спосіб показати результат).
  Висновки — у звіт; повні довідники — пропозиція у вигляді змін `src/shafa/catalog.py` (з датою звірки).
- HYP-4: **Стабільні селектори** — на що чіплятися (тексти підписів, `name`, ролі), щоб зміна дизайну Шафи не ламала все. Що робить робот, якщо поле не знайдено (стоп + скріншот + Картка в «Проблеми», не вгадувати).
- HYP-5: **Перевірка сесії** — як робот розуміє, що вхід є/злетів; що показати Власнику, якщо треба увійти знову.
Після Фази 0 зупинись: «ROBOT-001 фаза 0 готова».

3. `src/shafa/robot/`: відкриття профілю, перевірка входу, заповнення форми з Картки (`approved`): фото в порядку, назва, розділ, стан, бренд, поля розділу, опис, ключові слова, ціна. **Зупинка перед публікацією**, скріншот заповненої форми.
