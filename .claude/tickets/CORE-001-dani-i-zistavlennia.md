## Навіщо
Це перший шматок, який робить щось корисне: програма дивиться в Головну папку, бачить папки товарів, знаходить для кожної її пост у Експорті й записує Картку в базу. Те, що не вдалося зіставити, потрапляє в «Проблеми» з причиною простими словами. Усе далі (ціна, ШІ, екран перевірки, робот) будується поверх цієї бази.

Глосарій і правила — `docs/concept.md`, `docs/rules.md`.

## Фаза 0 — повністю, зупинка до коду
- HYP-1: **Формат Експорту.** Telegram Desktop (JSON) дає `{"name", "type", "id", "messages": [...]}`; у повідомленні `id`, `type` (`message` / `service`), `date`, `date_unixtime`, `text` (рядок **або** список із рядків і об'єктів `{"type", "text"}`), `text_entities`. Звір на справжньому `result.json` (Власник скаже, де він на Mac; **лише читати, у репозиторій не класти й не цитувати тексти у звіт**). Порахуй: скільки повідомлень, скільки з порожнім текстом, найменший і найбільший `id`, чи є поле про альбом (групу фото).
- HYP-2: **Альбоми.** Пост із кількома фото в каналі — це кілька повідомлень поспіль (різні `id`), текст лише в одного. Номер у назві папки — `id` із посилання на пост. Перевір на 7 прикладах (номери 1342, 1349, 1355, 1359, 1386, 1387, 1395): чи в повідомлення з цим `id` є текст. Відповідь визначає правило «де брати текст» (див. пункт 3). У каналі зараз публікується одне фото на пост, але старі пости можуть бути альбомами.
- HYP-3: **Назви папок.** Два варіанти: `1342` або `23948278241342` (= ідентифікатор каналу `2394827824` + номер поста). Ідентифікатор каналу в Експорті (`"id"` верхнього рівня) — `2394827824` чи з префіксом `-100`? Від цього залежить, як вирізати номер.
- HYP-4: **Фото в папках** — розширення `.JPG` великими (так у прикладах), можливо `.jpg` / `.jpeg`. Чи бувають у папці зайві файли (`.DS_Store`, `Thumbs.db`, `desktop.ini`).
Після Фази 0 зупинись: «CORE-001 фаза 0 готова».

## Що зробити (кожен пункт — окремий коміт)
1. **`src/shafa/db.py` — база.** Файл SQLite; схема створюється при першому відкритті; номер версії схеми в `PRAGMA user_version` (= 1). Таблиці:
   - `posts`: `post_id` (PK), `date` (ISO), `text` (звичайний текст), `source` (`export` / `bot`), `added_at`.
   - `items` (Картки): `id`, `folder_name` (UNIQUE), `post_id` (може бути NULL), `status`, `problem_code`, `problem_text`, `created_at`, `updated_at`.
   - `photos`: `item_id`, `position`, `file_name`.
   Статуси — один список у коді (enum): `new` (папка знайдена, чекає обробки), `review`, `approved`, `published`, `problem`, `archived`. У цьому тікеті ставляться лише `new` і `problem`; решта — заготовка для наступних тікетів.
2. **`src/shafa/export.py` — читання Експорту.** Повертає пости `post_id → (date, text)`. `text`-список склеюється в звичайний рядок (жодного форматування, посилання — як текст). Службові повідомлення пропускаються. Читання з `encoding="utf-8"`. Хештеги й ціну **не чіпати** — це CORE-002.
3. **Текст альбому** (за HYP-2): якщо в повідомлення з номером папки текст порожній, а поруч (сусідні `id`, той самий `date_unixtime`) є повідомлення з текстом — брати його. Якщо правило з HYP-2 інше — опиши в звіті й зроби як показали дані.
4. **`src/shafa/folders.py` — Головна папка.** Перелік папок товарів (лише перший рівень). З назви — номер поста: `^\d{1,7}$` → номер як є; починається з ідентифікатора каналу і далі цифри → решта. Фото: `.jpg`, `.jpeg` (будь-який регістр), сортування «як у провіднику» (`IMG_9.JPG` перед `IMG_10.JPG`). Службові файли ігнорувати мовчки. Ідентифікатор каналу — аргумент функції (а в CLI з `TELEGRAM_CHANNEL_ID`).
5. **`src/shafa/scan.py` — зіставлення.** Для кожної папки створити або оновити Картку. Повторний запуск нічого не дублює. Причини «Проблеми» — код + текст українською для неї:
   - `bad_folder_name` — «Назва папки не номер поста»;
   - `post_not_found` — «Поста з номером N немає в експорті» (бот — пізніше);
   - `no_text` — «У поста N немає тексту»;
   - `no_photos` — «У папці немає фото .jpg»;
   - `too_many_photos` — «Більше 10 фото»;
   - `duplicate_post` — «Дві папки для одного поста: A і B» (обидві в Проблеми);
   - `folder_missing` — «Папку не знайдено» (Картка `new` чи `problem`, папка якої зникла; Картки інших статусів не чіпати).
   Якщо Проблему виправили (додали фото, перейменували) — наступне сканування повертає Картку в `new` і чистить причину.
6. **CLI:** `python -m shafa scan --export <шлях> --root <шлях> --db <шлях>` друкує підсумок: «Папок: N · нових: N · у Проблемах: N» і список проблем (номер/назва папки + причина). Без кольорів і емодзі. `--root` за замовчуванням із `SHAFA_ROOT_DIR`. Читання `.env` — **не** в цьому тікеті: змінні беруться зі середовища.
7. **Тести** (`tests/`): фікстури лише вигадані — маленький `export.json` (5–8 повідомлень з вигаданими текстами: звичайний пост, `text`-список, службове, альбом) і тимчасова Головна папка в `tmp_path`, у тому числі з кирилицею в шляху (`Робочий стіл/Шафа`). Фото — порожні файли або згенеровані крихітні, **не справжні**. Перевірити кожну причину Проблем, повторний запуск без дублів, повернення з Проблем у `new`, обидва формати назви папки, сортування фото.
8. **Документи:** `CLAUDE.md` — коротко про модулі й команду `scan`; `docs/TECH_DEBT.md` — якщо щось відклав.
9. **Журнал** — останнім комітом.
