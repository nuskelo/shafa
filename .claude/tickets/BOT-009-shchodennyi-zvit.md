# BOT-009 — Щоденний звіт Власнику в Telegram

Вага: **Звичайна**. Аналоги: BOT-003 (нагадування ботом), `Core.tell_owner`, `bot_summaries`.

## Навіщо
Мета Власника — не перевіряти програму руками. Раз на день бот пише йому одне коротке повідомлення: що зроблено, що зламалось, що чекає його.

## Що зробити
1. Новий модуль `src/shafa/bot/report.py`:
   - `build(conn, data_dir, day) -> str` — текст звіту за календарну добу `day` (місцевий час, як ліміт доби робота). Лише читання бази й файлів.
   - Звіт (порожні рядки — пропускати; нулі — показувати лише для «Опубліковано»):
     ```
     📊 Звіт за 21.10
     Шафа: опубліковано N (сесій M); зупинка: <людська причина останньої сесії>
     Проблеми за день: N (коди → людські назви, по кількості, топ-5)
     Чекають тебе: На перевірку N · Схвалені N (у черзі на завтра)
     Пробний прогін: перевірено N, Проблем N   (з rehearse-last.json, якщо він за цю добу)
     Бот: нових постів N; сайт: надіслано N, помилок N
     ШІ: $X із $Y
     Самоперевірка: все гаразд | ⚠️ <перші 2 рядки fail/warn з health-last.json>
     ```
   - Ніяких секретів, chat id, шляхів. ≤ 4096 символів (обрізати хвіст «…»).
2. Коли слати:
   - Час — `SHAFA_REPORT_AT` у `.env` (типово `21:00`; порожньо/`off` — вимкнено). Лише `.env`, не «Налаштування» (як `SHAFA_REHEARSE_AT`).
   - Перевірка в `Core.tick`: настав час і за цю добу ще не слали → `say(owner_chat, …)`. Позначка «надіслано за <дата>» — файл `<дані>/report-last.json` (`db.py` не чіпати).
   - Ноутбук спав у 21:00 → надіслати при першому `tick` тієї ж доби; наступної доби — звіт «за вчора» один раз, якщо ще не слали, потім уже поточний.
   - Нема `owner_chat` → нічого не слати, без помилки.
   - Помилка Telegram → не позначати надісланим; наступна спроба не частіше ніж раз на 10 хв.
3. Команда `/zvit` у приватному чаті **лише Власника** → звіт за сьогодні зараз (позначку не змінює). Від Продавчині — як інші невідомі команди.
4. CLI: `python -m shafa report [--day YYYY-MM-DD]` — друкує текст, нічого не надсилає.
5. Людські назви причин зупинки й кодів Проблем — взяти з того, що вже показує панель/журнал робота (не дублювати словник; якщо його нема — один словник у `report.py`).
6. Тести (фейковий годинник і фейковий Telegram): текст на фікстурній базі; рівно одне надсилання за добу; сон → пізніше тієї ж доби; пропущена доба → «за вчора» один раз; `off`; нема `owner_chat`; помилка Telegram → повтор через 10 хв; `/zvit` від Власника працює, від Продавчині — ні; довжина ≤ 4096; секретів у тексті нема.
7. `CLAUDE.md` — рядок про `bot/report.py`; `.env.example` — `SHAFA_REPORT_AT=21:00` з коментарем.

## Гіпотези (Фаза 0)
- HYP-1: «доба» робота (ліміт) рахується в місцевому часі — знайти функцію і взяти її ж.
- HYP-2: у `sessions` є `published`, `problems`, `stop_reason`; час Проблеми видно з `items` (поле — знайти).
- HYP-3: `batch.spent_today` / `limits()` дають витрати і ліміт ШІ.
- HYP-4: `site_jobs` має статус і час для «надіслано / помилок за добу».
- HYP-5: `Core.tick` викликається регулярно і коли нема повідомлень.

## Заборони
- Живу Шафу не відкривати. У тестах — жодного справжнього Telegram/ШІ/сайту. Канал не чіпати (звіт — лише в особистий чат Власника).
- `.env` не чіпати (лише `.env.example`). `robot/guard.py`, `robot/browser.py`, `db.py` — не змінювати. RULES_VERSION не піднімати.
