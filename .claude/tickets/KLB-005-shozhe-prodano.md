## Що зробити
1. **Хто «схоже, продано»** (без мережі, у `refresh` після `sync`): (а) `klubok_ads.state = 'published'` з `klubok_id`, пост `known_gone` → `sold_asked`, `gone_at`; (б) `klubok_listings` `sold = 0`, `post_id` не NULL, пост `known_gone`, `asked_at` NULL і не прив'язане до (а) → у той самий список (позначка `asked_at` — коли показали). Оголошення вже не в її активних/«Обновить» (продане руками) → тихо `sold`, без питання.
2. **Екран:** «Проблеми» Клубку — блок «Схоже, продано (N)»: фото й назва її оголошення, «Відкрити на Клубку», пост і чому («пост 7333 зник з каналу ДД.ММ»), кнопки **«Так, продано — зняти з Клубку»** / **«Ні, ще продається»**. «Так» → `sold_ok_at` (чекає робота); «Ні» → `published` назад з позначкою «не питати» (для (б) — `asked_at` лишається, більше не показуємо). Лічильник «Проблем» Клубку враховує блок.
3. **Робот знімає:** `robot --klubok-marksold --db … [--human-click] [--limit N]` і на початку сесії публікації (після «Обновить все», до першої пари): для кожного `sold_ok_at` — `MarkSoldTicket(id)` → **один** GET рівно `https://klubok.com/users/198135?pg=marksold&id=<id>` (`page.goto`; `--human-click` — людина тисне посилання на сторінці керування) → пауза 3–6 с → наприкінці знімок: id у `type=2` чи `sold=True` / зник з активних і «Обновить» → `removed` (`removed_at`), подія `klubok.sold`; ні → гучна `klubok.sold_failed`. Ліміт за сесію 20, пауза між оголошеннями 5–10 с. 429/немає входу/капча — стоп як у публікації.
4. **Guard:** `MarkSoldTicket` пропускає рівно один GET з точним шляхом `/users/198135`, query рівно `pg=marksold&id=<id квитка>` (порядок параметрів як на сайті; інші параметри — блок). Усе інше `marksold`/`renew…`/`delete` — блок, як було.
5. Видаляти з «Проданого» — **ні** (позначки досить; рішення можна змінити пізніше).
6. `klubok_fake`: `?pg=marksold&id=` → оголошення в `type=2` + редирект на керування; сценарії: ок, «не змінилось», 429.
