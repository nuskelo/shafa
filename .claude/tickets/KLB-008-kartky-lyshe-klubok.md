## Навіщо
Влад хоче на Клубку все, чого там ще немає, у порядку: **хвиля 1** — старі пости (до бота) зимові/демісезонні/сумки (жін., чол., дит.), яких немає на Клубку → **хвиля 2** — пости бота підряд (усі типи) → далі одна черга з Шафою → **хвиля 4** — старі решта (спорт, літо, туфлі). Аналіз Архітектора 11.11 (канал 2525 живих постів × 1796 її оголошень): хвиля 1 ≈ 80–140 пар, хвиля 2 ≈ 60–90, решта ≈ 210–330. **Для старих достатньо одного фото** (у каналі в старих постів одне фото; рішення Влада 11.11).
Цей тікет — модель і черга (без нової вкладки: вкладка «Клубок» з Карткою, схваленням і «Старт» — KLB-009).

## Рішення Архітектора (DRIFT у Фазі 0 — зупинка)
**D1 · Картка «лише Клубок».** Схема 19: `items.only_klubok INTEGER NOT NULL DEFAULT 0`. Такі Картки **ніколи** не бачить Шафа: вкладки, лічильники, `publish.queue_rows`/`take`, `review` (кнопки Шафи), бот, звіт, здоров'я, `rehearse`, `borh` — усе читає лише `only_klubok = 0` (той самий підхід, що `sessions.site` у KLB-002; Фаза 0 — повний перелік читачів `items`).
**D2 · Схвалення для Клубку.** `klubok_ads.state` + `review` («чекає схвалення для Клубку»; таблиця перебудовується в міграції — CHECK). Картка «лише Клубок» після ШІ → `review` у `klubok_ads`; `queued` — лише після схвалення (функція `queue.approve(item_id)`; кнопка — KLB-009). Картки Шафи — як зараз: схвалила для Шафи → іде на Клубок без окремого схвалення.
**D3 · Хвилі.** `klubok_ads.wave INTEGER NOT NULL DEFAULT 2`. Порядок черги: `wave` ↑, далі як зараз (зимове → інше → «Літо», старіші пости першими). Хвиля 1 і 4 — лише з імпорту (D4); хвиля 2 — Картки Шафи з постом > `SHAFA_KLUBOK_FROM_POST` (Влад поставить на перший пост бота, ≈ 7000 — Фаза 0 знаходить точно: перший пост із «коментар» у тексті).
**D4 · Імпорт: `klubok-import --export <тека з result.json> --wave 1|4 [--dry-run]`** (на основі `import-old` / `borh.import_old`, `export.read_export`):
1. Пости Експорту з номером < межі (D3), класифікація з **тексту поста** (нове `klubok/waves.py`; правила — як у скрипті Архітектора: сумки → зима → туфлі → демі → спорт → літо → домашнє → одяг → інше за першим реченням; хвиля 1 = зима/демі/сумки, 4 = решта). Одяг / інше — не беремо.
2. Пост уже має Картку в базі (будь-який статус, крім архіву «продано») → **Картка Шафи — еталон**: новий рядок `klubok_ads` з цією `wave`, нової Картки немає; фото немає → одне фото з Експорту в її папку.
3. Пост без Картки → нова Картка `only_klubok = 1`, папка `<Головна>/Клубок/<пост>` (одне фото + текст), статус `new` → далі звичайний `fill` (ШІ) → `klubok_ads.review`.
4. Перед створенням — `dup.find` проти `klubok_listings` (знімок має бути свіжий): схоже → не імпортуємо, рядок у звіті «вже на Клубку». Пост зник (немає в Експорті) — не існує.
5. `--dry-run` — нічого не пише; звіт ≤ 60 рядків: скільки за типами, скільки еталонів Шафи, скільки нових, скільки «вже на Клубку».
**D5 · Продано.** Картка «лише Клубок» чий пост зник (`publish.known_gone`) → `skipped klubok_post_gone` (як зараз). Нічого автоматично не знімаємо (KLB-005).
