# CORE-014 — кілька розмірів однієї пари в одному пості → окрема Картка на кожен розмір

**Вага:** середня-велика (~45–60 хв). **Рішення Власника (21.10):** варіант А — окрема Картка на кожен розмір.
**Аналоги в коді:** `scan.text_problem` / `rules.many_sizes` / `rules.many_items` (зараз такі пости → Проблема `many_items`), `fill.recheck` (перерахунок без ШІ), CORE-015 `changes.py` (зміна поста), DUP-001 (схожі), ROBOT-011 (Картка з `shafa_id` ніколи вдруге).

## Навіщо
Пости «В наявності декілька розмірів» зараз ідуть у Проблеми й не продаються на Шафі. На Шафі покупець шукає за розміром, тож кожен розмір — окреме оголошення; продали один — інші лишаються.

## Приклади з бази пілоту (зараз `problem` `many_items`)
- **3654** Peter Storm: `* 43 розмір. Устілка 28см…` / `* 45 розмір. Устілка 29,3см…`, одна ціна 1800 внизу → 2 Картки: 43 і 45, обидві 1800.
- **3655** Peter Storm: `* Вказаний 37 розмір. Ідуть на 36…` / `* Вказаний 38 розмір. Ідуть на 37…`, 1900 → 2 Картки: **36** і **37** (правило «ідуть на»).
- **3659** Hi-tec: `* 38 … 1600грн` / `* 39 … 1700грн` / `* 42 …` (без ціни), внизу 1990 → 3 Картки: 38→1600, 39→1700, 42→1990 (ціна рядка, інакше спільна).
Ціна Шафи — за звичайним правилом (·1,15, вгору до десятка; 450–500 → 501; 950–1000 → 1001).

## Що зробити
1. **Розбір поста на варіанти** (`rules.py`, нова чиста функція, напр. `size_variants(text)`): рядки-пункти (`*`, `•`, `-`, `–`), у кожному рівно один розмір (з урахуванням «вказаний X, ідуть на Y» → Y), своя устілка/ширина, своя ціна або спільна. Варіанти — лише коли **все однозначно**: ≥2 пункти, кожен пункт = один розмір, розміри різні, одна модель (решта тексту спільна). Будь-що інше (різні моделі, пункт без розміру, два розміри в пункті, ціни без пунктів) → як зараз, `many_items`.
2. **Картки:** одна Картка на розмір. `folder_name` унікальний → суфікс розміру (напр. `borh-3654~43`, `3654~43`; знак — на твій вибір, у звіті). Фото — спільна папка поста (база без суфікса). `scan` для такої папки створює/оновлює Картки-варіанти, а не Картку без суфікса; повторний scan нічого не дублює.
3. **Бланк:** ШІ — **один запит на пост** (спільні поля); розмір, устілка, ціна — з рядка варіанта правилами. Опис для Шафи кожної Картки: спільний текст + лише її пункт; без «В наявності декілька розмірів» і без хештегів інших розмірів.
4. **Назва на Шафі:** з розміром наприкінці (напр. «… Peter Storm 43»), щоб оголошення відрізнялись. Фаза 0: подивись, як зараз складається назва.
5. **Дублі (DUP-001):** Картки-варіанти одного поста — **не** «схожі» між собою (спільні фото!). Виключи сестер з перевірки схожих, у т.ч. з `my_listings` (опублікована сестра — не дубль).
6. **Існуючі 3 Картки `many_items`** (3654/3655/3659): при `recheck` (вони вже в `RECHECK_PROBLEMS`) / на старті `app` — перетворити на варіанти без ШІ, якщо є збережена відповідь ШІ, інакше → `new` (ШІ один раз). Стара Картка без суфікса не лишається «висіти» (стає першим варіантом або в Архів з поясненням — вибір твій, у звіті). Жодна Картка з `shafa_id` не змінюється.
7. **Зміни поста (CORE-015) і видалення:** пост змінено → усі варіанти за правилами CORE-015. Пункт розміру зник з тексту → варіант `review`/`approved` → Проблема з людським текстом «Розмір X прибрано з поста — можливо, продано»; `published` → рядок у звіт (статус не міняти). Пост видалено (= продано) → усі варіанти, як зараз одна Картка.
8. **Ліміт на день:** кожен варіант = 1 оголошення (так і рахується, просто перевір).
9. **Екран:** у списку й на Картці видно розмір варіанта і «1 з 3» (сестри).
10. **Сайт — не чіпати.** Пости бота з кількома розмірами йдуть на сайт як зараз; у звіті напиши, що бачиш.
11. `docs/rules.md` — нове правило; `CLAUDE.md`; `docs/TECH_DEBT.md` за потреби.

## Гіпотези (Фаза 0)
- HYP-1: прив'язка Картки до папки йде лише через `folder_name` → суфікс + «база папки» вистачає; знайди всі місця, де з `folder_name` будується шлях до фото (робот, rehearse, precheck, health, changes).
- HYP-2: для варіантів не треба нової колонки (розмір видно з суфікса). Якщо треба — лише `ALTER TABLE … ADD COLUMN` міграцією, опиши у звіті.
- HYP-3: DUP-001 порівнює з `my_listings` і з іншими Картками — знайди обидва місця.
- HYP-4: RULES_VERSION піднімати не треба (3 Картки обробляються через `recheck` / окремий шлях). Якщо без підняття ніяк — поясни у звіті, чому.

## Заборони
- Живу Шафу не відкривати. Канали, бот, сайт, `.env` — не чіпати. `robot/guard.py`, `robot/browser.py` — не змінювати. `db.py` — лише міграція колонки, якщо HYP-2 вимагає.
- Справжніх запитів до ШІ, Telegram і сайту в тестах не робити. Вивід обрізай (`| tail -n 40`).
- Не вигадувати варіанти, коли розбір неоднозначний — краще `many_items`.

## Тести
- 3654, 3655, 3659 (тексти вище) → правильні розміри й ціни; 3655 — 36 і 37.
- Неоднозначні → `many_items`: два розміри в одному пункті; пункт без розміру; різні моделі; «43 і 45» без пунктів (як зараз).
- Один запит ШІ на пост, не на варіант.
- Сестри не «схожі»; опублікована сестра не робить іншу дублем.
- Повторний scan не дублює; стара Картка `many_items` → варіанти без ШІ (є відповідь).
- Пункт зник з тексту → Проблема / рядок у звіт; пост видалено → усі варіанти.
- Опис і назва кожного варіанта — лише свій розмір.
