# KLB-011 · Дублі Клубку вирішує програма: відбиток фото → ШІ-зір → лише тоді людина

**Вага:** критична (автоматичне рішення «виставляти / ні» на її акаунті, гроші ШІ, завантаження з чужого сайту). **Без міграції** (база 19). Фаза 0 зі **стопом**. **Автор:** Архітектор · 12.11.2026
**Гілка:** `feature/KLB-011-dubli-za-foto` від `origin/main` (083ea8c, є #106). Перший коміт: `.claude/handoff/KLB-010*.md` і `KLB-010-screens/` → `.claude/archive/handoff/`; цей тікет.

## Навіщо
На живій 12.11 у «Проблемах» Клубку **84** пари «схоже на вже виставлене» (правило за текстом: бренд/підтип + розмір + ціна). Вікторія мусить кожну дивитись очима. Влад: програма вирішує сама — **фото нашої пари проти фото її оголошення на Клубку; збіг → «дубль»; різні → ШІ-зір; ШІ не впевнений → лише тоді людина.**

## Як має працювати
1. **Усі схожі, не лише перше.** `klubok/dup.find_all(conn, card)` — усі оголошення, що проходять наявне правило (`same`, її активні + виставлені програмою), у тому самому порядку; `find` = перше з `find_all` (поведінка черги не змінюється).
2. **Відбиток фото** (`klubok/photo_dup.py`, лише Pillow, нових залежностей немає): dHash 64 біти (`exif_transpose` → сірий → 9×8). Наша пара — **усі** фото Картки (тека за `folders.photo_folder`, порядок Картки, ≤ 15) + `fields.spare_photo`; її оголошення — `klubok_listings.photo`; виставлене програмою — фото тієї Картки. Відстань = мінімум по наших фото. **≤ T1 → «дубль за фото»** (T1 — з Фази 0). Більше за T1 — нічого не доводить (вона могла поставити інше фото) → крок 3.
3. **ШІ-зір** — наявний `dup.Judge` (DUP-001: та сама модель, денний бюджет, журнал запитів, обережне правило) з адаптером Клубку: «Фото 2 — оголошення на **Клубку**», факти — назва, ціна, розміри з `klubok_listings`. Наше фото для ШІ — найближче за відбитком. Shafa-поведінку `dup.py` не міняти (лише параметр сайту / адаптер).
4. **Рішення по Картці** (усі кандидати):
   - хоч один «дубль» (фото або ШІ `yes`) → як «Так, дубль»: `skipped klubok_dup_yes`, `dup_klubok_id` = той, з ким збіглось, `klubok_listings.post_id` (як `queue.dup_yes`), текст «Дубль — фото збіглось з оголошенням N» / «Дубль — ШІ: …»;
   - усі кандидати ШІ `no` → як «Інша пара — виставити» (`queue.dup_other`, `dup_ok_at`);
   - інакше лишається `problem klubok_duplicate` для людини: `dup_klubok_id` = перший непевний, `problem_text` з «ШІ не впевнений: …» (формат `dup.verdict_text` — екран показує слова ШІ в рядку «Проблем»);
   - кандидатів > 3, оголошення програми ще `publishing` (id немає) → людина, без ШІ.
5. **Коли:** `klubok/dupcheck.py` `check(conn, root, fetch, judge, limit)` бере `problem klubok_duplicate`, ще не перевірені (маркер у `problem_text`: «ШІ не впевнений» / «Фото не порівняно: …» — `queue._write` рядки `problem` не переписує, HYP-4). Кличе: (а) `refresh.Background` **після** `sync`, у тому самому потоці (екран не чекає); (б) CLI `python -m shafa klubok-dups [--dry-run] [--no-ai] [--limit N] [--db …] [--root …]`, звіт ≤ 60 рядків. Тимчасове (мережа, 429, бюджет ШІ вичерпано, немає ключа) — без маркера, спробує наступного разу; постійне (немає нашого фото, фото не читається) — маркер «Фото не порівняно: …» → людина.
6. **Завантаження її фото:** лише `https://img.klubok.com/…` (як `snapshot.PHOTO`), GET без cookies через `httpx2`, тайм-аут 15 с, ≤ 5 МБ, `image/*`, пауза 0,5–1 с між запитами, 429/403 → стоп завдання (подія), кеш `<дані>/klubok-photos/<id>.jpg`. Браузер і guard не потрібні (робот не запускається).
7. **Слід і відкат:** кожне авторішення — тиха подія `klubok.dup_auto` (Картка, оголошення, спосіб: «фото, відстань N» / «ШІ», слова ШІ). «Ще ▸ Архів» Клубку — група «Дубль — вирішила програма» з посиланням на її оголошення і кнопкою **«Ні, це інша пара — виставити»** (→ `queued`, `dup_ok_at`). «Схвалені» — мітка «Інша пара (ШІ)» для `dup_other` від програми. Над «Проблемами» Клубку — рядок «Програма вирішила: X дублів, Y інших пар · вам лишилось Z».

## Фаза 0 — **стоп** «KLB-011 фаза 0 готова»
Копія бази — від Власника (команда нижче), `--dry-run`, нічого не пише. Головну й `<дані>/klubok-old` живої — **лише читати**; її фото — у тимчасову теку.
- **HYP-1:** `klubok_listings.photo` віддається GET без cookies (код, `content-type`, розмір, пікселі — 3 приклади).
- **HYP-2:** на справжніх дублях її фото на Клубку — те саме фото, що в пості (перестиснуте/зменшене). Таблиця на всі **84** `problem klubok_duplicate` копії: Картка, пост, оголошення, мін. відстань, яке наше фото, чи є наше фото. **Контроль:** ≥ 300 пар «Картка × чуже оголошення» з уже завантажених фото (Картка з одним оголошенням — проти фото **інших** оголошень; нових завантажень не треба) — розподіл відстаней. Запропонуй T1, за якого в контролі **0** хибних «дубль»; скільки з 84 вирішить фото.
- **HYP-3:** `dup.Judge` підходить через адаптер без зміни поведінки Шафи (файл:рядок, що саме параметризуєш).
- **HYP-4:** `queue._write` не переписує рядки `problem` (маркер у `problem_text` живе) — файл:рядок.
- **HYP-5:** скільки з 84 без жодного нашого фото (стерто й немає запасного).
- **ШІ на пробу:** 10 пар, які фото не вирішило (≤ 0,25 $): `yes/no/unsure` + слова.
- Аркуш для очей Архітектора/Влада: `.claude/handoff/KLB-011-pary.html` (наше фото | її фото | відстань | вердикт фото | вердикт ШІ), фото зменшені до 200 px.
- Звіт `.claude/handoff/KLB-011.md` ≤ 40 рядків.

## Ітерація 1 · рішення по Фазі 0 (Архітектор · 12.11.2026)
Аркуш переглянуто (1620, 583, 2287 — те саме фото, відстань 0; у 1620 її сумка на Клубку двічі: 36264689 і 36949068).
- **D1.** Відбиток — **`/m/` + центральний квадрат нашого фото, T1 = 4** (виміряно, 0 хибних). **Для ШІ — `/l/`** (1024×768, без обрізки): адресу будуємо заміною `/m/` → `/l/` лише за точним шаблоном `https://img.klubok.com/…/m/<id>_<N>.jpg`; не вдалось (не той шаблон, ≠ 200, не `image/*`) — ШІ отримує `/m/`. Кеш окремо: `klubok-photos/<id>.jpg` і `<id>-l.jpg`; `/l/` качаємо лише для кандидатів, що йдуть на ШІ. Переміряти T1 на `/l/` — не зараз: новий **TD** (повне фото проти повного могло б зловити 3635-подібні).
- **D2.** Так: `_write` не затирає `problem_text`, коли новий стан `queued` **і** `dup_ok_at` не NULL. Текст програми — з префіксом «Інша пара — ШІ: …» (за ним мітка в «Схвалених» і лічильник Y); людське «Інша пара» лишає текст NULL. Будь-який інший новий стан (`skipped` — пост зник, поля) переписує як раніше. Тест: два `sync` поспіль — мітка жива; пост зник → `skipped` з причиною.
- **D3.** Так: фото-крок для всіх; > 3 кандидатів — без ШІ (людина), але збіг фото → «дубль».
- **D4.** Так: `Verdict.retry` (Шафа ігнорує); `dupcheck` перевіряє фото/бюджет/ключ до `Judge`; `retry=True` — без маркера.
- **Знахідка «знімок змінився»:** так, `dupcheck` щоразу рахує `find_all`, `dup_klubok_id` — лише для екрана; кандидатів 0 (оголошення продане) → `dup_other` з текстом «Інша пара — схожого на Клубку вже немає».
- **Адаптер `site`:** як у звіті (ціна поста, без `other_post`, слова «Клубок» в інструкції й підписах). Інструкцію Клубку — окремим файлом `prompts/duplicate-klubok.md` (Шафа не змінюється байт у байт).
- Ліміт ШІ за один прохід `Background` — 40 запитів (решта — наступного разу); CLI `--limit` — як у тікеті.
