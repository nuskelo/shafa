# SITE-002 · На сайт — через 7 днів; видалене з каналу = продано (сайт і Шафа)

> Архітектор, 18.10.2026. Гілка `feature/SITE-002-tyzhden` від свіжого `origin/main`. Першим комітом — тікет, STATUS.md, перенесення `.claude/handoff/CORE-008.md` в `.claude/archive/handoff/`.

## Рішення Власника (18.10)
- Нові пари з бота йдуть на viktoriashoes **не одразу, а через 7 днів** після поста в каналі. Схвалення немає.
- Вона видаляє пост з каналу **лише коли продано**. Видалено до 7 днів → на сайт не йде ніколи. Видалено після → на сайті «Продано».
- Старі ~2093 пари, імпортовані сайтом, теж стежимо: зник пост → «Продано».

## Фаза 0 (зупинись, якщо чогось немає)
Прочитай контракт `~/Documents/ShoeStore/docs/integration/shafa-helper-api.md`. Потрібні: (1) як позначити пару проданою / зняти з продажу за номером поста; (2) як отримати список номерів постів усіх пар на сайті (або перевіряти по одній). Якщо чогось немає — **не вигадуй**: запиши точні питання до Архітектора сайту в handoff, зроби все інше, а виклик «Продано» — за інтерфейсом із заглушкою, що лише пише в журнал (TD).

## Механізм
1. **Перевірка «пост ще є».** Bot API не дає подій видалення й історії каналу. Перевірка: `forwardMessage` (або `copyMessage`) поста з каналу у службовий чат (її/Власника приватний чат з ботом — обрати один, тихо: `disable_notification`) і **одразу видалити копію**. Помилка «message to forward not found» / «MESSAGE_ID_INVALID» = видалено. Інша помилка (мережа, 429, 5xx) = **невідомо**, нічого не робити, спробувати пізніше. Ніколи не вважати «немає зв'язку» продажем.
2. **Черга сайту.** `site.enqueue` ставить `not_before = posted_at + 7 днів` (налаштування «Чекати днів перед сайтом», типово 7; 0 = одразу, як зараз). Стан `waiting` → у день виходу: перевірка «пост є» → є: текст **на цей день** (якщо бот отримує `edited_channel_post` — оновлювати збережений текст; інакше брати останній відомий) → відправка як зараз; немає: `cancelled` (на сайт не йде), у журнал.
3. **Продане.** Щоночі (раз на добу, у тиші, напр. о 03:00, якщо програма запущена; інакше — при наступному запуску) перевіряти пости пар, що вже на сайті (`done`): зник → «Продано» на сайті (Фаза 0). Старі ~2093: список із сайту; перевіряти по колу з урахуванням лімітів Telegram (≈1 запит/с у приватний чат; 429 → Retry-After) — скільки встигне за ніч, решта наступної. Записувати `checked_at` по кожному посту.
4. **Шафа (лише не публікувати видалене):** перед публікацією нового поста (7 днів чекання) — та сама перевірка; видалено → Картка в Архів «Пост видалено з каналу — продано», не публікувати. Знімати з Шафи продане — НЕ в цьому тікеті (BOT-002).
5. **Екран:** у «Налаштуваннях» — «Чекати днів перед сайтом» і «Перевіряти продане щоночі» (типово увімкнено). На панелі — рядок «Сайт: чекає N · вийде сьогодні M · продано за тиждень K».

## Межі
- Перемикач «Відправляти на сайт» лишається головним: вимкнено — нічого не йде і не позначається проданим.
- Перевіряти лише канал `TELEGRAM_BOT_CHANNEL_ID`. Нічого в каналі не редагувати й не видаляти (видаляти лише свої копії у службовому чаті).
- 2+ невдалі перевірки підряд «невідомо» для поста — не продаж; після 3 діб «невідомо» — повідомлення Власнику.

## Тести
Видалено до 7 днів → не на сайт; є через 7 днів → на сайт з новим текстом; помилка мережі/429 → не продаж; зник після відправки → «Продано»; копія в службовому чаті видаляється; ротація старих з лімітом; Шафа: видалений новий пост → Архів, не публікація. Telegram і сайт — фейки; справжніх даних і `.env` тести не бачать. Мутації як у CORE-007.
