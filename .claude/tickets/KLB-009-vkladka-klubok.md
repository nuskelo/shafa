## Навіщо
Зараз Клубок керується лише з термінала (Влад). Вікторія має працювати з Клубком так само, як із Шафою: перемкнулась на «Клубок» → бачить чергу, схвалює старі пари (Картки «лише Клубок» після ШІ), вирішує дублі, тисне «Старт». Шафа не змінюється.

## Що зробити
1. **Перемикач угорі «Шафа | Клубок»** (`base.html`), той самий стиль. Клубок — адреси `/klubok/...`. Шафа — як зараз (`/` = Шафа).
2. **Вкладки Клубку** (з лічильниками, той самий `list.html`-вигляд, пошук як у Шафи):
   - **«На перевірку»** — Картки `only_klubok = 1`, статус `review` (після ШІ);
   - **«У черзі»** — `klubok_ads.state = 'queued'` у порядку `queue.place` (хвиля, зимове першим), колонка «хвиля»;
   - **«Треба рішення»** — `klubok_ads.state = 'problem'` (дублі, «перевірте, чи опубліковано», помилки форми);
   - **«Виставлено»** — `published` (дата, «Відкрити на Клубку»);
   - **«Не піде»** — `skipped`, згруповано за причиною (без фото, пост зник, не та категорія…).
3. **Картка у Клубку** (`/klubok/item/N`):
   - блок **«Як буде на Клубку»** з `fields.ad`: назва, ціна, шлях категорії, розміри, стан, колір, бренд, фото в порядку; чого бракує — жовтим із причиною (`klubok_*` коди);
   - Картка «лише Клубок» (`review`): поля Картки редагуються як у Шафі (той самий `card.html`, жовті поля), кнопки **«Схвалити для Клубку»** (`review.approve_klubok`) / **«Не виставляти»** (→ `archived`, причина «не для Клубку») / «Далі →»;
   - Картка Шафи: блок «Як буде на Клубку» лише для читання + посилання «Відкрити в Шафі»;
   - дубль — наявні кнопки «Інша пара — виставити» / «Так, дубль»;
   - «перевірте, чи опубліковано» — поле «номер оголошення на Клубку» → `queue.confirm` (KLB-007, свіжий знімок), і кнопка «Ні, не опубліковано — повернути в чергу» (нове `queue.retry`: `problem klubok_uncertain` → `queued`, лише з екрана, запис у `events`).
4. **Панель робота Клубку** (у вкладках Клубку; на основі `panel.html`/`robot/control.py`):
   - **«Старт»** → `robot --klubok-publish --limit N` (N = залишок ліміту доби), той самий `control.spawn`, журнал у `klubok-run.log`;
   - **«Пауза» / «Стоп»** — сесія Клубку слухає ті самі команди, що й Шафа (`publish.command`): Стоп — після поточної пари; Пауза — між парами;
   - стан наживо: «виставлено X з N · зараз: пост P · далі через M хв», останній підсумок сесії, причина зупинки людською мовою (`klubok_publish.STOPS`);
   - **«Увійти в Клубок»** → `robot --klubok-login`; **«Оновити її оголошення»** → `robot --klubok-snapshot`; дата знімка й кількість;
   - поки працює будь-який робот — «Старт» обох сайтів недоступний з поясненням (спільний замок).
   - `--human-click` на екрані немає.
5. Налаштування — блок «Клубок» як є.
6. `docs/klubok.md` (розділ «Екран») і `CLAUDE.md`.

## Фаза 0 (стоп лише при DRIFT)
- HYP-1: `review.Card` / `card.html` показують Картку `only_klubok` без кнопок Шафи (KLB-008 їх відмовляє) — що лишити, що сховати.
- HYP-2: `klubok_publish` можна навчити `publish.command` (Пауза/Стоп) без зміни Шафи; `control.state` уміє `site = 'klubok'`.
- HYP-3: `fields.ad` для екрана — швидко (без `dup.find`); дубль показується з `klubok_ads`.
- HYP-4: Ctrl+C-логіка KLB-003 (доробити поточну) = «Стоп» з екрана.

## Доказ
- Шафа без змін (наявні тести вкладок/панелі зелені; вкладки Шафи не бачать «лише Клубок»).
- Схвалити для Клубку → Картка в «У черзі» з хвилею; «Не виставляти» → не в черзі.
- «Старт» Клубку запускає підставний процес з правильними аргументами; при живому роботі Шафи — недоступний; Стоп/Пауза доходять до сесії Клубку (підставний Клубок).
- `queue.retry` — лише з `problem klubok_uncertain`; інші стани — відмова.
- Браузерні тести вкладок (той самий стиль, що UI-тести Шафи), телефон/вузький екран не ламається.
- `make ci` зелений; `quality` на PR зелений.
