# BOT-001 · Telegram-бот: пост від Продавчині → канал + папка з фото

**Вага:** критична (секрет — токен бота; публікація в її живий канал; чужий API). Фаза 0 повністю, **зупинка до коду**.
**Автор:** Архітектор · 13.10.2026
**Гілка:** `feature/BOT-001-bot` від `origin/main` після `git fetch` (після мержу PR #10).
**Перший коміт:** цей тікет і `.claude/state/STATUS.md` від Архітектора.

## Навіщо
Зараз Продавчиня публікує пост у каналі руками, а потім окремо створює папку з фото для Шафи. Бот робить це одним кроком (рішення 11.3): вона надсилає боту текст + фото → бот **одразу** публікує в канал **перше надіслане фото + текст + підпис** «Пишіть сюди 👉 @viktoriaviktoriatg» → **усі** фото кладе в `<Головна папка>/<номер поста>/` → текст поста записує в базу (`posts.source = 'bot'`). Далі все як зараз: через 7 днів пакет ШІ → перевірка → робот.

## Правила (незмінні)
- Бот слухає **лише** чат Продавчині (`TELEGRAM_SELLER_CHAT_ID`) і Власника (`TELEGRAM_OWNER_CHAT_ID`). Від інших — мовчки ігнорувати (і не відповідати).
- Токен бота — лише в `.env` (Власник кладе сам, як ключ ШІ). Ні в коді, ні у виводі, ні в логах, ні у звіті.
- Робота через довге опитування (long polling) з ноутбука; без вебхуків і серверів (OQ-007 — окремо).
- Один пост — одна публікація в канал: повторна доставка того самого повідомлення Telegram'ом (після обриву) не дає другого поста в каналі (запам'ятовувати оброблені `update_id`/`media_group_id`). Тест.
- Живі перевірки — **спершу в тестовому каналі** Власника, не в її каналі. Її канал — лише з дозволу Власника в чаті.
- Публікує в канал лише після явної команди-підтвердження від неї? → **питання HYP-6**.

## Фаза 0 — повністю, зупинка до коду
- HYP-1: **Бібліотека.** Bot API напряму через HTTP-клієнт, що вже є в залежностях (`httpx` від `anthropic`?), проти бібліотеки (`python-telegram-bot`, `aiogram`). Критерії: кількість нових залежностей (TD-005), Windows, тести без мережі. Рекомендація.
- HYP-2: **Альбом.** Кілька фото з підписом приходять кількома повідомленнями з одним `media_group_id`, підпис — лише в одному. Як зібрати альбом (пауза N секунд), як визначити «перше надіслане фото» (порядок у альбомі). Ліміт: до 10 фото в альбомі.
- HYP-3: **Якість фото.** Фото «як фото» Telegram стискає (~1280 px), «як файл» — оригінал. Що краще для Шафи і ШІ; що робити, якщо надіслано файлом HEIC/PNG (Шафа й наш код чекають JPG) — конвертувати Pillow чи відхилити з поясненням. Ліміт завантаження файлів ботом (20 МБ).
- HYP-4: **Публікація в канал:** `sendPhoto` з підписом (ліміт підпису 1024 символи — що, якщо текст довший?). Як отримати номер нового поста (`message_id`) — це і є номер папки. Бот має бути адміном каналу з правом публікації — як перевірити на старті.
- HYP-5: **Номер папки:** `message_id` з каналу = номер поста, як у посиланні `t.me/c/…/1234` і в Експорті — звір на тестовому каналі.
- HYP-6: **Підтвердження перед публікацією.** Варіант А — публікує одразу (рішення 11.3). Варіант Б — бот показує прев'ю «Так опублікую: [фото] [текст + підпис]» і кнопки «Опублікувати / Скасувати». Б захищає від помилкового надсилання. Рекомендація з причинами — **питання для Власника**.
- HYP-7: **Коли програма вимкнена:** Telegram тримає непрочитані повідомлення бота до 24 год. Що бот робить на старті з чергою, і як повідомляє їй «опубліковано із запізненням».
Після Фази 0 зупинись: «BOT-001 фаза 0 готова».

## Що зробити (план; уточнимо після Фази 0)
1. Читання `.env` для токена й чатів (як для ключа ШІ), перевірка прав бота в каналі на старті.
2. Прийом повідомлень: текст + 1–10 фото (альбом), фільтр чатів, захист від повторів.
3. Публікація в канал (перше фото + текст + підпис), створення папки `<номер поста>`, збереження всіх фото в порядку надсилання (JPG), запис поста в базу.
4. Відповідь їй: «Опубліковано: <посилання>. Збережено N фото для Шафи.» або зрозуміла помилка («Надішли хоча б одне фото», «Текст задовгий…»).
5. Запуск бота разом з екраном (окремий процес, як робот), стан на панелі «Бот: працює / вимкнений / помилка».
6. Тести без мережі (підставний Telegram): альбом у різному порядку, повторна доставка, чужий чат, HEIC/PNG, довгий текст, немає фото, немає прав у каналі.
7. **Живий прогін у тестовому каналі** (з дозволу Власника): 3 пости — одне фото, альбом 5 фото, фото файлами.
8. `CLAUDE.md`, TD, журнал — останнім комітом.
