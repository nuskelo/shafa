## Навіщо
Зараз ШІ запускається командою `fill` по одній Картці, ~4,4 ¢ за штуку. Для щоденної роботи Продавчині потрібно: одна кнопка на екрані «Оновити», яка сама знаходить нові папки і відправляє їх на ШІ **пакетом** (вдвічі дешевше) з **кешованою інструкцією** (TD-011), а нові пости бере в роботу лише через 7 днів після публікації в каналі (рішення 11.4 — не платити за те, що продасться в Telegram). Ціль — ≤ 2 ¢ за Картку.

## Фаза 0 — повністю, зупинка до коду
- HYP-1: **Кешування інструкції** (prompt caching) у поточному SDK `anthropic==1.9.0` з моделлю з CORE-003: як позначити кешовану частину, мінімальний розмір, час життя кешу, ціна запису й читання. Чи працює кеш у пакетному режимі (Batch). Документація Anthropic — посилання й цитати у звіт.
- HYP-2: **Batch API**: створення пакета, статус, забирання результатів, ліміти (кількість запитів і розмір пакета з фото), скільки зберігаються результати, як скасувати. Як прив'язати результат до Картки (`custom_id`).
- HYP-3: **Вартість:** оцінка на Картку для трьох варіантів — зараз (≈4,4 ¢), пакет без кешу, пакет + кеш. Розрахунок з цін документації, без запитів.
- HYP-4: **Дата поста** для правила 7 днів — `posts.date` з Експорту (час Telegram) — звір формат і часовий пояс.
- HYP-5: **Що вже є:** `fill`, `dry-run`, ліміт 10 за запуск, `ai_requests` (облік вартості) — що з цього перевикористати.
Після Фази 0 зупинись: «CORE-004 фаза 0 готова». **Жодних запитів до API до рішення Архітектора.**

## Що зробити (план; уточнимо після Фази 0)
1. Кешування інструкції в звичайних запитах і в пакеті (TD-011).
2. Пакетний режим: Картки `new`, чий пост старший 7 днів (налаштування, типово 7) → один пакет; статус Картки `ai_pending` (міграція), щоб не відправити двічі; забирання результатів → бланк → `review`. Помилка окремого запиту → `problem` `ai_error`.
3. **Запобіжник грошей:** ліміт Карток на пакет (налаштування, типово 50) і ліміт витрат на добу в доларах (типово $3); перевищення → не відправляти, на екрані пояснення. Облік фактичної вартості — в `ai_requests` (з урахуванням знижки пакета й кешу).
4. **Екран:** кнопка **«Оновити»** на панелі: `scan` → пакет для готових Карток → «Відправлено на ШІ N товарів, результати зазвичай до години» ; при відкритті екрана й кожні кілька хвилин — забрати готові результати. Лічильник «чекають ШІ: N», «чекають 7 днів: N». Кнопка **«ШІ, спробуй ще раз»** у картці «На перевірку» (звичайний запит одразу, не пакетом; ручні правки не стираються — UI-001 D2).
5. TD-016: фото опублікованих Карток шукати в «Опубліковано».
6. CLI: `fill --batch` (відправити), `fill --collect` (забрати), `fill --estimate` (оцінка без запитів).
7. Тести без мережі (підставний клієнт): правило 7 днів на межі, повторна відправка неможлива (`ai_pending`), ліміти грошей і кількості, частково невдалий пакет, кеш позначено правильно, «спробуй ще раз» не стирає правки.
8. **Ручний прогін** (з дозволу Власника): пакет з 7 прикладів `~/Downloads/ШІ` (копія бази, правило 7 днів для них виконано) — фактична вартість на Картку у звіт. Порівняти з CORE-003 (3,1 ¢ / 4,4 ¢).
9. `CLAUDE.md`, TD (закрити TD-011, TD-016), журнал — останнім комітом.
