# PHOTO-001 — фото старих постів видаляються через 3 дні після публікації + HEIC з iPhone

**Вага:** середня (~45 хв). **Рішення Власника (21.10):** «старі фото через 3 дні після того, як виставилось на Шафу, видаляти». Закриває TD-030 і TD-023.
**Аналоги:** `robot/publish.purge_published` (папки «Опубліковано» через `DELETE_AFTER` = 3 дні, лише при `SHAFA_DELETE_PUBLISHED`), CORE-014 (спільна папка сестер — коли опубліковано всіх), `bot/core.py` прийом фото (зараз JPG/PNG).

## Навіщо
1. Фото старих постів (`<дані>/borh/<номер>/`) після публікації лишаються назавжди — тека даних росте. Мають видалятися так само, як папки нових постів: через 3 дні після публікації.
2. Якщо Вікторія надішле боту фото з iPhone файлом (HEIC/HEIF), бот його не приймає.

## Що зробити
1. **Старі пости:** у тому самому прибиранні, що й `purge_published` (і за тим самим налаштуванням `SHAFA_DELETE_PUBLISHED`), видаляти `<дані>/borh/<база назви>/` Карток `published` з `published_at` старше 3 днів. Варіанти (CORE-014) — лише коли всі сестри опубліковані й найпізніша старша 3 днів. Записати `purged_at`. Видаляти лише всередині `<дані>/borh/` (перевірка шляху, як `folder.parent == …`).
2. Картка з `purged_at` ніде не шукає фото як помилку: самоперевірка, precheck, rehearse, CORE-015 `sync_photos` (зниклі фото опублікованої Картки — не `photos_missing`). Перевір усі місця.
3. На панелі/у звіті о 21:00 — одним рядком «Прибрано фото: N постів» (якщо N > 0).
4. **HEIC:** бот приймає HEIC/HEIF (документом і як фото) і зберігає як JPG (якість як для наявних JPG, EXIF-поворот застосувати). Бібліотека — `pillow-heif` (закріпити версію в `pyproject.toml` і lock-файлі; перевір, що є колесо для Windows amd64 / Python 3.12 і macOS arm64 — у звіті). Не вдалося прочитати → людське повідомлення Продавчині «Не можу відкрити це фото — надішліть, будь ласка, як звичайне фото» і рядок Власнику.
5. `CLAUDE.md`, `docs/TECH_DEBT.md` (TD-030, TD-023 закрити).

## Гіпотези (Фаза 0)
- HYP-1: фото старих постів лежать лише в `<дані>/borh/<номер>/` і після публікації більше ніде не потрібні (робот, сайт, DUP-001 беруть фото з Шафи/`my_listings`, не з теки).
- HYP-2: `purged_at` уже ставиться для «Опубліковано» — те саме поле годиться для `borh`.
- HYP-3: `pillow-heif` ставиться pip-ом без системних бібліотек на Windows і macOS.

## Заборони
Живу Шафу не відкривати. Канали, сайт, `.env` — не чіпати. `robot/guard.py`, `robot/browser.py`, `db.py` — не змінювати. Нічого не видаляти поза `<дані>/borh/` і `<Головна>/Опубліковано/`. Справжніх запитів до Telegram, ШІ, сайту в тестах не робити. Вивід обрізай (`| tail -n 40`).

## Тести
`borh` опублікованої 4 дні тому — видалено, 2 дні — ні; `SHAFA_DELETE_PUBLISHED` вимкнено — нічого; Картка не `published` — ніколи; варіанти — лише коли всі; шлях поза `borh` — ніколи; після прибирання самоперевірка/precheck/`sync_photos` не дають помилки; HEIC (маленький тестовий файл у `tests/data`) → JPG; битий HEIC → людське повідомлення.
