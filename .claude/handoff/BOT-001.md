1. Фаза 0:
   - **HYP-1 → рекомендація: прямий HTTP через `httpx2`.** Він уже стоїть як залежність `anthropic` 2.13.1; закріпимо `==` явно, нових пакетів не буде. Потрібно ~7 методів: `getMe`, `getUpdates`, `getChatMember`, `getFile`, `sendPhoto`, `sendMessage` і для варіанта Б ще `answerCallbackQuery`/`editMessageReplyMarkup`. Для тестів є `httpx2.MockTransport` — без мережі. Бібліотеки тягнуть більше: `python-telegram-bot` 22.8 — `httpx` (інший пакет) і asyncio; `aiogram` 3.31 — aiohttp, pydantic, magic-filter, aiofiles. **Безпека (DRIFT):** токен стоїть в адресі (`/bot<token>/METHOD`, файли — `/file/bot<token>/…`), а текст помилки `httpx2` (`HTTPStatusError`) містить цю адресу — перевірено локально. Тому обгортка замінює кожну помилку своєю (`from None`) і не друкує адрес; журнал httpx2 вимкнений.
   - **HYP-2 частково.** `media_group_id` є в документації. Як приходять частини альбому і де стоїть підпис, документація не описує — **UNKNOWN**, звірю на тестовому каналі. План: збирати частини з одним `media_group_id` до паузи ~3 с, «перше фото» — найменший `message_id`, ≤ 10 фото.
   - **HYP-3.** Її канал (Експорт): усі 2504 фото — 1280 px по довшому боці (Telegram стискає). Папки для Шафи (`ШІ`) — оригінали 4032 px, 1,4–3,3 МБ. Фото файлом приходить оригіналом, `getFile` віддає ≤ 20 МБ. ШІ однаково зменшує до 1092 px, тож 1280 вистачає ШІ; для Шафи краще оригінал. Pillow 12.3 HEIC не читає (перевірено) — HEIC треба або відхиляти з поясненням, або додати залежність `pillow-heif`. PNG → JPG через Pillow.
   - **HYP-4 VERIFIED.** `sendPhoto`: підпис 0–1024 символи «after entities parsing»; фото file_id-ом — «no limits», завантаженням — ≤ 10 МБ; повертає `Message` з `message_id`. **Фото, надіслане файлом, file_id-ом як фото не відправити** («can't change the file type») — його треба завантажити заново. Її тексти в Експорті: максимум 853 символи з підписом, понад 1024 — 0 зі 2507. Права бота: `getChatMember(канал, id бота)` → `can_post_messages`. Канал в API — `-100` + id каналу.
   - **HYP-5.** `message_id` — «Unique message identifier inside this chat». Кожен її пост — одне повідомлення з одним фото (2504 з 2515). Що номер у відповіді `sendPhoto` збігається з номером в Експорті й у посиланні — **UNKNOWN до тестового каналу**.
   - **HYP-6 → рекомендую Б (прев'ю + «Опублікувати / Скасувати»).** Причини:
     - публікація в живий канал майже незворотна;
     - Б природно збирає текст і фото, надіслані окремими повідомленнями;
     - Б рятує від дублів: якщо вона надішле пост удруге, поки бот вимкнений, обидва дійдуть до бота, а з Б вона підтвердить лише один.

     Ціна — одне натискання. **Питання для Власника.**
   - **HYP-7 VERIFIED.** Непідтверджені оновлення Telegram тримає ≤ 24 год. Підтвердження — `getUpdates` з `offset` > `update_id`. На старті бот обробляє чергу по порядку й відповідає: «отримано о ГГ:ХХ, опубліковано із запізненням». Старше 24 год — втрачено, бот про це не дізнається (OQ-007).
   - **DRIFT (безпека, як у робота).** Якщо бот впаде між `sendPhoto` і записом у базу, після перезапуску він повторить пост. План: записувати «публікую» в базу до `sendPhoto`; невизначена відповідь → «Перевір канал», без повтору. Плюс таблиця оброблених `update_id` (вимога тікета).
   - Готове в коді: `posts.source = 'bot'` і `scan.save_posts` не перезаписує пости бота (`scan.py:52`); назва папки `1342` вже розпізнається; `SIGNATURE` у `rules.py:55` ловить «Пишіть сюди 👉 @…»; `control.spawn` годиться для окремого процесу.
